# 技能维护者规程（不参与任务生成）

> 仅维护/修订技能时使用。本文治理技能自身，不是验收契约内容；生成任务书时不得内联本文。

## 纠偏分流

用户指出缺口时，先证明应属于哪一层，不默认向主技能加闸：

| 缺口类型 | 去向 |
|---|---|
| persona、真实入口、用户判据、用户语言缺陷、安全红线 | SUA/ACG 核心 |
| 长任务调度、WAITING、收判、超时、最小断点 | 所有模式共享的 SINGLE_WRITER 基础内核 |
| 并行写者租约、CAS、fencing、分片归并、接管 | 仅 PARALLEL_UNATTENDED 扩展规范 |
| 驱动器、主机、端点、项目环境经验 | 项目 playbook/fixtures |
| 产物命名、树形、链接、报告格式 | artifact 规范 |
| 技能路由、发布、版本和修订流程 | 本维护者规程 |

只有影响用户旅程、判据真值、安全或证据完整性的规则才允许进常驻核心。

## 机械闸与退役

- 新增闸必须给一正一反样例，并声明作用域、预算耗尽行为、合法终态和报告映射。
- 同时回答替代了哪条旧规则、失效条件是什么；纯增量须说明适用边界。
- 每版本检查连续两个版本未被返工/缺陷/纠偏引用的闸，列退役候选；禁止只增不减。
- 不得把「用户再次指出」直接转化为核心机械闸，先完成上述分层。

## 变更同步

任何条款修订按影响面核查：正文、Verification Checklist、受影响 references、模板、self-check-gates、样例、README、catalog 镜像和路由回归。

同步不仅是字段存在：必须做跨文件语义冲突扫描、正反样例、当前版本与 changelog 对账。涉及 frontmatter description/routing 时跑 train 与 held-out 回归；不得为通过检查而改写预期样例。
