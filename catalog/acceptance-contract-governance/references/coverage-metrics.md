# 覆盖度量口径（唯一权威）

> 本文件是「高覆盖面」的量化口径**唯一权威源**：acceptance-contract-governance（生成/治理侧）与 simulated-user-acceptance（执行侧，自检 #15、§8.1.14）共引本文，任何一侧不得另行定义分子分母细则。技能本体不依赖 Python/Node/Shell；本文「机验」只规定**算什么与判定口径**，用执行环境任意可用工具或阅读推理完成，工具缺失时降级手工对账并留痕。

## 1. 三个度量（执行期，报告头机算）

| 度量 | 公式 | 分子细则 | 分母细则 |
|---|---|---|---|
| 需求覆盖率 | 有产品验证落判的需求源条目数 / 需求源条目总数 | 归宿桶 ∈ {覆盖, ⏸️} 的需求条目——⏸️=已执行有观察、标准冲突待裁定，产品侧验证已发生 | 覆盖对账节（§10.1 或等价节）逐条登记的需求源条目总数 |
| UI 证据覆盖率 | 有判定时截图/DOM 的 UI PASS 数 / UI PASS 数 | 判定时的截图或 `[DOM]` 记录；事后补证不计 | 全部 UI PASS 数；<100% → 报告头写「UI PASS 证据覆盖 N/M」并判 INTERIM |
| 未触率 | 未触（BLOCKED）数 / AC 总数 | 未触归因审计后的 BLOCKED 计数（OMITTED 已补做或转归因者不计） | §3 主表全集唯一数（scan 口径） |

**⏭️ 不计入需求覆盖率分子**。⏭️ 是「有证据的未实现/不适用」声明：它闭合该点（收官闸意义的终态归宿），但产品侧验证未发生，不构成覆盖率意义的落判。此细则把执行侧「有终态落判」操作化为「有产品验证落判」——两词之差即 38/45 与 45/45 之差。

实证（某全域轮任务书）：45 条需求 = 覆盖 34 + ⏭️ 7 + ⏸️ 4 + 纯未覆盖 0 → 需求覆盖率 = (34+4)/45 = 84.4%；另 7 条 ⏭️ 为产品未实现，不压测试责任、也不垫覆盖率。

分母为 0 → 写 N/A+理由；三项均机算，禁止手填估算。

## 2. 设计期度量（生成期，任务书头部/回执）

| 度量 | 内容 | 闸 |
|---|---|---|
| 需求归宿分布（四桶） | 覆盖 / ⏭️ / ⏸️ / 纯未覆盖 各机验数 | 四桶计数与头部声明逐桶一致；**纯未覆盖必须为 0**（ac G4 P1）；回执七项摘要必报 |

四桶定义（设计期口径）：

- **覆盖**：≥1 个验收点承接该需求条目；
- **⏭️**：产品未实现/不适用，标 ⏭️ **且带声称出处 + 侦察证据**（缺任一 → 桶位无效，视同纯未覆盖）；
- **⏸️**：源间口径冲突，挂 ⏸️ **且进冲突登记表**（§8 或等价节，缺登记 → 桶位无效）；
- **纯未覆盖**：无任何承接且无上述任一理由——**出现即返工**。

## 3. 机验算法

### 3.1 归宿四桶计数

1. 定位覆盖对账节（§10.1 或「需求对账」语义节），逐需求行取尾格桶位；
2. 尾格归一化：去（…）/(...) 注释与空白 → 覆盖 / ⏭️ / ⏸️ 三值之一（`⏸️ C5` 这类记 ⏸️）；
3. 判定：四桶计数 == 头部声明（「覆盖 A / ⏭️ B / ⏸️ C」）逐桶相等，且 A+B+C == 需求行总数。

### 3.2 §3.5 深度表并集闭合（含同域缩写展开）

1. 主表全集 = self-check-gates §1 scan 口径（区间扫描 + 门槛前缀行收集）；
2. §3.5 各行按 `AC-<域>-<基号><接续令牌>*` 抽取，接续令牌两种：
   - `~NNN` 区间 → 展开为 基号..NNN **全号段**（`AC-IMP-201~218` = 201..218 逐号展开）；
   - `/NNN` 列举 → 追加该号（`AC-IMP-202/210/215` = {202, 210, 215}）；
3. 取并集 U_D，**双向**对账：
   - 主表有而 U_D 无 = **漏标维度** → 返工；
   - U_D 有而主表无 = **幽灵标注** → 返工。

**陷阱实证（某全域轮任务书审计）**：裸正则只抓首号，会把 `201~218` 误读为单点 201、把 `203/204` 误读为 203——曾致并集 94/128、假差集 34 项；按上法展开后为 127/128，唯一真差集 = 1 个漏标维度的 AC（书写缺口，1 点）。**本闸禁止裸正则上岗**（凡含正则的闸先一正一负活体测，见 SKILL.md Verification Checklist 总则）。

## 4. 反 gaming 与禁用口径

- **不设及格线**：三度量只报数 + 机验口径一致，不设「≥X% 通过」线——产品未实现会压低需求覆盖率，设线只会逼虚标 ⏭️/乱挂 ⏸️；
- ⏭️ 虚标拦截 = §2 出处+证据双要件；⏸️ 虚标拦截 = §2 登记表要件；桶位无效视同纯未覆盖（返工）；
- 禁止以历史任务书的需求条数为分母（派生口径不作 basis）；禁止跨轮拼接覆盖率；禁止把 ⏭️ 计入需求覆盖率分子（§1）。
