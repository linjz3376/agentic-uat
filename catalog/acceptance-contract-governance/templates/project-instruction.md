**多角色、多账户原则**：全域场景按 persona/角色切换对应测试账户；涉及不同权限时明确列出各账户别名、角色/权限与负责的场景/AC，凭据只引用密钥源。管理员、普通用户、审计/只读等角色各走自己的旅程，并用跨角色正反向用例验证权限边界；禁止全轮只用一个账户，也禁止用高权限账户代替低权限角色完成验收。只有确认系统确实为单角色时，才可声明单账户并写明依据。

**跨块缝隙判据**：旅程中每次「换块」的接缝是最高危区——登录态/权限态/数据态在块间是否延续（A 块收藏的知识在 B 块个人中心可见；A 块删除在 B 块搜索即时消失），每个接缝一个验收点。

**造数规范**：同块级口径——测试数据必须像真实用户会造的数据（真实语义的标题/正文/分类），**禁 test123/aaa/111 类垃圾数据**；真实用户行为本身是探索判据的一部分。
**心智模型判据**：UX 主观项引用用户熟悉的对标产品（网盘/微信/知乎/百度百科…），判据写成「与用户心智模型一致：<对标产品怎么做的>」。

**域批场景（全域轮强制）**：每个有深度点的域设一条 `G-DOM-<域>` 场景——persona=该域典型角色，旅程=该域核心内容旅程（不跨块），**关联 AC-ID 列承接该域全部深度点**（批占位或逐点列表，批注点数=该域计划点数、与 §1 对账一致）。作用=「孤儿点不许存在」在全域尺度的机制落点：深度点默认挂靠域批场景，主线跨块旅程（G1~Gn）只挑 ≥2 块穿过的流量最高路径扩挂；纯机制点归管理员/运维场景沿用块级口径。场景挂靠集合=主线扩挂 ∪ 域批承接 ∪ 机制点，三集合不重不漏对应 §3 主表全集——域批批注点数与 §1 域计划点数、§3 该域实际点数三方一致（对不上=返工）。

## 6. 执行者手册（任意 AI agent 拿到本文档即可执行，设计基线）

### 你是谁
你是 §0 各场景的 persona（G1~Gn=跨块旅程角色；G-DOM-<域>=该域典型角色；G0=全域自由探索）。全程以该用户的心智操作：他想完成什么、他看到什么、怎样算成功/受阻。**遇到文档没写的情况，按「真实用户会怎么办」处理并记录**——你不是逐条打勾的机器人。

### 用什么操作
使用执行环境可用的浏览器或桌面交互方式（人工操作、自动化工具均可，工具名称仅为示例）。按产品实际入口导航，按**用户可见标签**操作。多角色账户使用独立浏览器上下文/profile 或等价隔离方式，防止会话串用。

**浏览器能力清单（开工环境闸的一部分，逐项实测打勾）**：①打开 URL 并等待预期元素可见（非盲等固定时长）②真实点击/输入/选择 ③判定时截图（判定同时刻留存，事后补图只能标「事后补证」）④捕获下载事件（文件名+字节数）⑤处理对话框（prompt 可输入、confirm/alert 可辨识）⑥读页面文本/DOM。缺某项：受影响控件记「有意跳过+浏览器能力缺口」并在报告声明——不得静默跳过或改判。

**桌面客户端通道能力清单**（涉桌面客户端类入口时逐项核对）：①窗口枚举含最小化实例（不得按可见性/尺寸过滤）②动作前截图验证目标窗口真在前台（异窗/锁屏=停跑+告警，禁盲打点）③物理分辨率截图（DPI 感知；经工具回读降采样时按物理分辨率换算坐标）④剪贴板读写（文本注入+回读校验）⑤真实键鼠事件派发。缺某项=该通道结构性不达标，降级入口或换通道，禁止硬跑。

**拟人操作纪律**：必须用真实事件操作（点击/输入/选择/键盘），禁止把「打开页面+截图」当操作；每个操作后必须验证可观察变化（页面变化/网络请求/下载事件/弹窗），无变化记「操作无响应」转缺陷候选；prompt/confirm/alert 必须真实处理双路径；读到的链接 href 直达仅限「同目标等效」且在日志记理由。

### 执行规程
1. §2 环境自检 → GO/PARTIAL/NO-GO；台账核对：头部「缺陷台账快照」行核对 ⛔ 门槛，台账不可达→按快照行日期决策并在报告注明
2. 执行顺序 **G1→Gn 场景优先**（⛔/高风险场景优先），域顺序只做 AC 回归；每场景先基本流，再 ≥2 备选流、≥2 异常流（N/A+理由除外）；G-DOM-<域> 场景承接该域全部深度点
3. 判定纪律：有辅证无 UI 判定=未验；唯三可跳（⛔ 未修/⏭️ 无实现/⏸️ 口径挂起只实测记录）；禁止假装通过。UI 写点必须真实点按钮、处理 confirm/alert/prompt、记录保存后回显
4. **控件级覆盖**：每个涉验页面的每个可操作控件真实操作 ≥1 次并登记控件操作矩阵（页面×控件×动作×操作后观察结果×证据）；只加载不点算漏测；写控件受载体/授权约束记「有意跳过+理由」
5. ❌ → 十段式缺陷（用户语言）；证据落盘；S0/G0 记录四栏笔记
6. 每场景一句场景级结论 → §11 汇报 → 按 Final-Report-Gate 三态选 final-report 或 interim-report

### 凭据与证据边界
本文档零明文；每账户别名对应其获准的密钥源引用，注入方式由执行平台决定，不假设固定变量名；不得整轮只用一个账户、不得跨角色借用高权限账户。以 persona 经产品实际提供入口可见的结果为判定主证；源码/DB/日志/内部接口只能作辅证，不得替代用户侧判定；机器入口点按契约断言判定（状态码/错误码/幂等/鉴权/字段），接口 200 不等于通过。
