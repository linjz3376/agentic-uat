# 产物树与文件命名规范

> 配套 `simulated-user-acceptance` §7.6 自检闸与 §8.3 产物树。目标：任何项目、任何执行者，产物结构一致、可检索、可审计。
> 优先级：任务书产物树 > 本默认；两者皆无 → 报告不合规。

## 1 目录结构

```
<report-root>/                        # 默认 tests/reports/<YYYY-MM-DD>-<domain>/
├─ execution-log.md                   # 必需
├─ defects.md                         # 必需
├─ final-report.md                    # FINAL / FINAL-WITH-GAPS（三态口径见 §4.1）
├─ interim-report-<YYYY-MM-DD>.md     # INTERIM（与 final 二选一）
├─ evidence/                          # 必需
│  ├─ <AC-ID>_<步骤>_<yyyyMMddTHHmm>.png
│  ├─ <AC-ID>_<步骤>_<yyyyMMddTHHmm>.txt   # DOM/网络原始记录
│  └─ <AC-ID>_<步骤>_<yyyyMMddTHHmm>.json  # 接口响应
├─ imports/                           # 有上传动作时必需
│  ├─ <原文件名>（或 <用途>_<AC-ID>_<yyyyMMddTHHmm>.<原扩展名>）
│  └─ <用途>_fail-detail_<batch>.<原扩展名>
├─ exports/                           # 有下载动作时必需
│  └─ <用途>_<AC-ID>_<yyyyMMddTHHmm>.<原扩展名>
└─ exploration/                       # 可选
   └─ g0-<YYYY-MM-DD>.md
```

## 2 文件职责

| 文件 | 必须包含 | 禁止包含 |
|---|---|---|
| `execution-log.md` | 环境闸判定、基线重采、逐 AC 行（状态/层级/实际/证据/缺陷/备注）、方法覆盖、B 点勾选 | 大段报告正文；凭据 |
| `defects.md` | 已定性表（编号/级别/类别/复现/预期/实际/影响/证据）、待定性表（编号/可能类别/源A/源B/影响/待裁定/风险预判）、统计、风险接受清单、阻塞项 | 已关闭且无留痕的项；凭据 |
| `final-report.md` | 未触=0 核验行、总览/域/维度分布、缺陷双口径、对账、残留、结论 | 与 interim 并存 |
| `interim-report-<date>.md` | 未触 N 点声明、final 暂缓、已完成部分结论 | 「终期/收官/final」称谓 |
| `evidence/` | 判定同时刻截图/录屏/DOM/网络 | 事后补拍冒充；无关个人数据 |
| `imports/` | 原始夹具、失败/重复明细 | 二次编辑过的文件 |
| `exports/` | 原始下载文件 | 手工改写过的文件 |

## 3 命名细则

### 3.1 证据文件

```
<AC-ID>_<步骤>_<yyyyMMddTHHmm>.png
例：AC-NMPOOL-002_emptySearch_20261027T1135.png
```

- 步骤用英文短词（search/submit/confirm/export），避免空格与中文；
- 时间戳为本地时间 `yyyyMMddTHHmm`；
- 同一 AC 多张证据按步骤区分，不覆盖。

### 3.2 导入/导出文件

```
<用途>_<AC-ID>_<yyyyMMddTHHmm>.<原扩展名>
例：nm-uat-valid-1_AC-NMIMP-007_20261027T1237.xlsx（xlsx/csv/zip 等均按原扩展名保留）
```

或保留源系统文件名时，在报告/台账中登记映射关系。

### 3.3 缺陷编号

```
已定性：DEF-<项目>-<YYYYMMDD>-<三位序号>
待定性：DEF-<项目>-<YYYYMMDD>-P<两位序号>（保留原冲突号交叉引用）
```

### 3.4 报告时间

- `interim-report-<YYYY-MM-DD>.md` 用**报告日**，不用开始日；
- 同一天多份阶段报告追加 `-2`、`-3` 后缀并登记。

## 4 覆盖与降级规则

| 情形 | 处理 |
|---|---|
| 任务书指定了产物树 | 以任务书为准；技能默认仅补齐缺失项 |
| 任务书只指定部分 | 指定部分用任务书，其余用本默认 |
| 任务书未指定报告根目录 | 目录语义裁决（跨语言通用口径）：`test/`=单元测试用例目录（单测套件，非本技能管辖）；`tests/`=验收验证产物目录（本技能产物树的家）。优先级链：①项目文档/AGENTS 已声明验收产物目录 → 从之；②仓库已存在承载验收产物的 `tests/` → 用之（不新建平行目录）；③两者皆无 → 缺省 `tests/reports/<YYYY-MM-DD>-<domain>/`；项目拒绝 tests 形态时用 `.uat/<date>-<domain>/`。⚠️ 不得把验收产物写进 `test/`——那是单测用例的家。产物是否入 VCS=项目 VCS 策略，本技能不规定（owner 口径：tests/ 与 test/ 均可不入库） |
| 无写入权限 | 先请求获准位置，不向任意目录落盘；在报告中注明「产物位置受限」 |
| 单点小任务（<5 步） | 可只保留 `execution-log.md` + 证据；报告可并入台账末尾，但须标注「轻量模式」 |

## 4.1 未触归因与重做记录

未触项必须在台账与报告中带归因，禁止只写「未触 N 点」。

### 归因四分法

| 归因 | 判定 | 必备证据 | 闭环 |
|---|---|---|---|
| UNREACHABLE | 换人/换时间再试仍不可达 | 尝试证据：登录失败截图、接口 404/403、无权限提示、造数失败记录 | 写解除条件 + 提供方 |
| OMITTED | 条件具备但没做 | **无尝试证据即默认 OMITTED** | 立即补测；不能补则写重做计划（负责人 + 日期） |
| DEFERRED | 主动决定不做 | 接受人 + 日期 + 理由 + 影响评估 | 进风险接受清单 |
| N/A | 功能不存在 | 入口/接口存在性确认 | 改记 ⏭️，不计未触 |

**默认规则**：未触项无「尝试证据」→ 一律按 OMITTED 处理。这条用于堵「把漏测说成环境不可达」。

### 未触清单模板

| AC | 归因 | 尝试证据 / 重做计划 / 接受记录 | 解除条件 | 影响面 |
|---|---|---|---|---|
| AC-XXX | UNREACHABLE | 登录失败截图 evidence/xxx.png | 提供 U-READONLY 账号 | 3 点权限矩阵无法验 |
| AC-YYY | OMITTED | 补测计划：2026-10-28 由 A 执行 | — | 主流程已覆盖，边界待补 |
| AC-ZZZ | DEFERRED | 接受人：产品负责人 X，2026-10-27 | 造数能力具备时补 | 5 万导出上限无法验 |

### 报告状态判定

| 条件 | 状态 | 文件 |
|---|---|---|
| 未触=0 | FINAL | `final-report.md` |
| 未触>0，全部 UNREACHABLE/DEFERRED 且有证据/接受 | FINAL-WITH-GAPS | `final-report.md`（头部声明未触数、归因、接受人） |
| 存在 OMITTED 未补做 | INTERIM | `interim-report-<date>.md` |

- OMITTED 补测完成后，未触数减少；归零或全部转 UNREACHABLE/DEFERRED 后状态可升级。
- FINAL-WITH-GAPS 的头部必须包含：`未触 N 点 | 归因分布 | 接受人 | 解除条件`。
- 禁止：未触>0 且标 FINAL 却不声明缺口；把 OMITTED 写成 UNREACHABLE；无重做计划的 OMITTED。

## 4.2 未触审计与补测拉起

### 审计规则（逐条判定，禁止凭感觉）

| # | 规则 | 判定 |
|---|---|---|
| A1 | 有可复核证据（截图/DOM/响应体/错误码 + 时间戳 + 步骤）且指向外部阻塞 | UNREACHABLE |
| A2 | 无证据，或证据仅为文字描述/无时间戳/不可复现 | **OMITTED** |
| A3 | 同域同条件 AC 已有成功执行者，未说明差异 | **OMITTED** |
| A4 | 无法判断 | 保守判 **OMITTED** |

### 防伪校验

1. 尝试证据必须是原始记录，文字描述不算；
2. 随机抽 1~2 个 UNREACHABLE 按证据复现，失败即降级；
3. 同域同条件部分能执行、部分不能，必须写明差异。

### 补测状态机

```
BLOCKED → 审计 → ├─ UNREACHABLE（合格）→ 解除条件，结束
                  ├─ OMITTED → OMITTED-PENDING → 补测 → ✅/❌/PARTIAL 或转 UNREACHABLE
                  └─ 不能立即补 → 补测任务单 → INTERIM
```

### 补测任务单模板

| AC | 前置条件 | 预计耗时 | 负责人 | 期限 | 状态 |
|---|---|---|---|---|---|
| AC-XXX | 需 U-READONLY 账号 | 10min | A | 2026-10-28 | 待补 |

### 审计记录模板（写入台账/报告）

| AC | 原归因 | 审计判定 | 依据 | 补测结果 | 最终状态 |
|---|---|---|---|---|---|
| AC-XXX | BLOCKED | OMITTED | 无尝试证据 | ✅ 补测通过 | ✅ |
| AC-YYY | BLOCKED | UNREACHABLE | 登录失败截图+时间戳 | 未补 | BLOCKED（附解除条件） |

### 禁止

- 无尝试证据却标 UNREACHABLE；
- OMITTED-PENDING 残留未清就出报告；
- 补测时修改原判定标准；
- 用「环境问题」一句话代替证据。

## 4.3 场景与 UI 主证

报告必须包含三张表，缺一即 INTERIM：

1. **场景完成表**：S-ID / persona / 基本流 / 备选流 / 异常流 / 交接 / 挂靠 AC / 完成状态 / 证据；每场景一句「作为 <persona>，我 能/不能 完成 <业务目标>」。
2. **UI 证据覆盖表**：UI AC 总数 / PASS 数 / 有判定时截图或 DOM 的 PASS 数 / 覆盖率；低于 100% 在报告头写「UI PASS 证据覆盖 N/M」。
3. **G0/SBTM 记录**：时间盒（全域 20min/块级 10min）、四栏笔记（观察/疑问/缺陷/覆盖）、新增 B 点/缺陷/未覆盖。

规则：

- `[UI]` 点 PASS 必须有判定时截图或 `[DOM]`；API 响应/DB/日志只能辅证，单独出现最高 PARTIAL。
- UI 写点必须真实点击控件、处理 confirm/alert/prompt、记录保存后回显；API 直调不算 UI 点通过。
- 事后补拍截图只能标「事后补证」，不得升级原判定。

## 4.4 报告前产物闸

出报告前逐项机验，任一不通过=报告不合规（先修产物，不修口径）：

1. **树形对账**：实际目录 vs **任务书产物树**（优先）或本文件 §1 默认树，差集必须为空；任务书树缺 `defects/`、`run-log.md`、`coverage-table.md` 等列名时逐项补齐，不得用 `execution-log.md` 静默代替 `run-log.md`（除非任务书允许）。
2. **根目录白名单**：只允许任务书树列出的文件/目录；`results.json`、`baseline.json`、`counts.json`、`obs-*.json`、`governance-self-check.md` 等扩展产物，必须集中在 `obs/` 或 `appendix/` 并在报告附录声明，不得散落根目录。唯一例外：`defect-ledger-<YYYY-MM-DD>.md`（台账快照，与 defects.md 并列于根级，来源纪律见第 9 项）。
3. **证据文件名正则**：`^AC-[A-Z0-9]+-\d+_.+_\d{8}T\d{4}\.(png|json|txt|md|pdf|bin|xlsx)$`；`page.png`/`details.json` 类短名一律不合格；目录层级按任务书（扁平或 `<AC-ID>/` 均可，但必须与任务书一致）。
4. **脚本隔离**：执行脚本不得放报告根；放 `tooling/`（或任务书指定目录）并在 `run-log`/`execution-log` 登记。
5. **证据清单**：证据数 >20 时生成 `appendix/evidence-manifest.json`（旧名→新名/AC/步骤/时间/用途），可追溯。
6. **报告头声明**：扩展产物、脚本目录、证据 manifest 位置必须在报告附录声明，否则视为自创文件。
7. **链接可达性（零断链）**：报告树内全部 Markdown 相对链接逐条解析存在性——`[x](path)` 的 path 相对所在文件解析后必须存在；断链=报告不合规（修链接，不修口径）。
8. **树外引用纪律**：引用报告树外文件（如跨轮 `tests/reports/defect-ledger.md` 台账）必须用 `../` 前缀相对路径 + 显式「树外」标注；裸文件名引用（如「详见 defect-ledger.md」）按本树解析必然断链=不合规。
9. **台账快照来源纪律**：报告根 `defect-ledger-<日期>.md` 必须存在，横幅注明来源二选一——活源可达=复制活源（来源=活源+复制时刻）；**活源不可达（被删/移动）=以任务书头部「缺陷台账快照」行+本轮新增缺陷重建**（来源=任务书快照行+重建时刻）。两种来源都须在报告注明。禁止与活源同名（不得叫 `defect-ledger.md`，日期后缀为最低区分）；并列 defects.md 为刻意设计，不视为扩展产物。
10. **缺陷单文件化**：**十段式原文的唯一事实源=跨轮台账**——每条新缺陷登记时即把十段式原文写入台账详情节（禁止只写进轮报告树）；各轮报告根 `defects.md`=汇总视图+**该轮新增**十段式的报告侧副本（内联节）；各轮报告根 `defect-ledger-<日期>.md`=台账全量快照——**快照在手=全部缺陷原文在手，任何一轮报告不得依赖跨轮树**。任务书 `defects/DEF-*.md` 目录形态=历史快照格式，按定义权归属以本侧为准。

11. **缺口类扫描（修复类任务收尾必做）**：任何产物修复完成后，先将缺口归入类别（命名/链接/落位/权威/引用/齐全性），再对报告树同类实例**全扫一遍**方可收官——防「问一层修一层」式挤牙膏。判定口径：本树同类零残留=过；手段不限（肉眼/脚本均可）。
12. **机验脚本自检（断言先于打印）**：临时校验脚本输出任何「通过」结论前——①先写断言（无断言的打印禁用）；②用一正一负两个样例**活体测一次脚本本身**（已知坏样例必须被判坏）方可采信其输出——防验证剧场。判定口径：负例未触发=该脚本全部输出作废；手段不限。

## 4.5 报告内容 15 条清单

报告必含以下 15 项，缺一即不合规（状态门槛见 §4.1；三表要求见 §4.3）：

1. 系统/版本/环境/执行时间；角色账户矩阵（不含凭据）。
2. 每场景 persona、目标、是否完成、用户感受、关键证据。
3. 每 AC 终态（✅/❌/PARTIAL/⏭️/⏸️/BLOCKED）。
4. **未触清单**：AC / 归因（UNREACHABLE/OMITTED/DEFERRED）/ 尝试证据或重做计划或接受记录 / 解除条件 / 影响面。
5. **未触审计结果**：OMITTED 检出数、补测完成数、补测后转归因数、残余 OMITTED-PENDING（必须为 0 或报告为 INTERIM）。
6. 覆盖矩阵：L1/L2/L3、B 点执行率、方法覆盖回执。
7. 缺陷：双口径统计（总数=已定性+待定性；已定性 P0~P3；待定性 高/中/低）+ 两张明细表 + 风险接受清单。
8. 对账：路由、需求条目、不变量、数量。
9. 残留数据与清场记录。
10. 缺陷集群、下轮建议、未覆盖与残余风险声明（含专项测试不适用范围）。
11. **场景完成表**：S-ID / persona / 基本流 / 备选流 / 异常流 / 交接 / 挂靠 AC / 完成状态 / 证据；每场景一句「作为 <persona>，我 能/不能 完成 <业务目标>」。
12. **UI 证据覆盖表**：UI AC 总数 / PASS 数 / 有判定时截图或 DOM 的 PASS 数 / 覆盖率；低于 100% 必须在报告头写「UI PASS 证据覆盖 N/M」，并直接判 INTERIM。
13. **G0/SBTM 记录**：时间盒、四栏笔记、新增 B 点、缺陷、未覆盖项；缺记录=未完成。
14. **覆盖度量行（机算，放报告头）**：需求覆盖率 / UI 证据覆盖率 / 未触率三项均由 results.json 机算，禁止手填估算；分母为 0 时写 N/A+理由。公式与分子分母细则以 acceptance-contract-governance `references/coverage-metrics.md` 为唯一权威。
15. **控件操作矩阵（机算）**：涉验页面数 / 页面可操作控件总数 / 已操作数 / 有意跳过数（含理由）/ 覆盖率；引用 obs/control-matrix.json；低于 100%（除有意跳过）不得出 FINAL 系报告。

## 4.6 执行契约与收判包 schema（3.3.35 收编——格式唯一权威，SKILL 正文与各模板一律指针引用，禁手写重述）

执行契约（锚 `Execution-Contract`，文件=`<报告树>/obs/contract.md`，建树时创建）字段：

1. **登记写者**（载体标识，轮次唯一，过户显式——并行会话只写叙事日志）
2. **状态唯一事实源**（本报告树状态表路径）
3. **未登记判定清单**（初始空；判定当回合登记并划除；回合末必须为空，非空=三件套不齐）
4. **任务与下一拍**
5. **闸门与红线**（含撞车红线/落点断言）
6. **开场自检卡**（5 行：读契约承继义务/判定·登记原子化/回合末四件套/落点断言后判定/非阻塞不停手）
7. **用例间基线清单**（每场景开场断言：在途=预期/无 pending ask/队列态已知；偏离先清障再执行）

收判包（无人值守定时链每个触发消息自带，收判回合零上下文可完成判定+登记）字段：探针标识/期望判定要素/台账写入模板+路径/（可选）前置状态快照（如权限存储快照）。

## 5 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 自创 `report.md` / `bugs.md` / `冲突.md` | 跨项目无法检索，审查者找不到 | 用固定名 |
| 冲突单独建 `conflicts.md` | 双源维护、统计分裂 | 并入 `defects.md` 待定性表（§4.4-10 单文件化） |
| final 与 interim 同时存在 | 违反闸门，读者不知道该信哪份 | 二选一，未触=0 才出 final |
| 证据放根目录或临时目录 | 报告迁移后断链 | 统一放 `evidence/` |
| 事后补截图当判定证据 | 证据失真 | 判定同时刻留证；补拍须标注 |
| 报告树内裸引树外文件（无 `../` 前缀） | 读者按本树路径解析必然断链 | 跨树引用必须 `../` 前缀+树外标注；报告前跑 §4.4 第 7/8 项机验 |
| 台账快照与活源同名或深埋 obs/ | 与活源混淆、评审翻找不到 | 快照必须命名 `defect-ledger-<日期>.md`、根级与 defects.md 并列（§4.4 第 9 项） |
| 十段式每缺陷一个文件散落 defects/ | 评审翻文件、链接易断 | 内联 defects.md 末节单文件（§4.4 第 10 项） |
| 导入/导出文件手工改名后仍引用原名 | 对账断链 | 保留原名或登记映射 |
| 只在对话里给结论，不落盘 | 无审计记录 | 结论必须落盘 + 报告引用 |
