# 方法论覆盖与模板

> 配套 `simulated-user-acceptance` §0 至 §3 各方法节。用途：把「边界之外」的测试方法补进验收流程，避免只验主流程+边界、漏掉组合/状态/不变量/无障碍/国际化/故障注入。
> 原则：细节放本文件，`SKILL.md` 只保留引用与门槛，防止技能膨胀。

## 0 风险档与适用性（先于方法数量）

| 风险档 | 适用对象 | 组合与操作口径 |
|---|---|---|
| 关键档 | 安全、越权、资金、隐私、不可逆、主旅程 | 适用高风险组合、非法转换和独特控件行为全做；不得用预算抽样降格，预算不足如实 INTERIM |
| 标准档 | 一般业务功能与关键数据 | 等价类+边界代表、Pairwise、主状态路径和独特控件行为；共享字段去重 |
| 探索档 | 低风险、重复展示、等价导航 | 可代表抽样；未做项进入残余风险，不伪装覆盖，也不计计划内 OMITTED |

- test basis 条目和页面清单仍须全量归宿；风险档只裁剪**行为组合执行**，不得删需求或静默漏页。
- 每 AC 在生成期标风险档和适用方法；无输入/状态/异步等语义的方法写 N/A+理由。
- 计划锁定后，计划内未做且无预算/授权证据=OMITTED；计划外的候选组合不进入未触分母，只进入残余风险。

| 判定表 | 设计 | 多条件组合 → 条件/动作表（§2.2） |

| 错误推测 | 设计 | 变异假设 6 至 10 条（§2.16） |

## 2 模板

### 2.1 等价类代表值表

| 字段 | 有效等价类 | 代表值 | 无效等价类 | 代表值 |
|---|---|---|---|---|
| 号码 | 11 位数字 | 19011034550 | 长度≠11 / 非数字 | 1901103455、1901103455a |

### 2.2 判定表

| 条件\规则 | R1 | R2 | R3 | R4 |
|---|---|---|---|---|
| 有效状态=有效 | Y | Y | N | N |
| 分配状态=未分配 | Y | N | Y | N |
| 动作 | 允许作废 | 拦截 | 拦截 | 拦截 |

规则：关键档且条件数不超过 3 时可做全规则；条件数达到 4 或标准/探索档组合膨胀时必须转 Pairwise/高风险组合抽样，保留全部非法与高风险规则。不可达规则标 N/A 并说明；不得同时要求同一条件集做 2^n 全量和 Pairwise。

### 2.3 Pairwise 降维

条件 ≥4 个（如 有效状态×分配状态×号卡状态×时间范围）时：
1. 列出每条件取值；
2. 生成全配对组合（工具或手工两两覆盖）；
3. 保留全部「非法组合」与「高风险组合」，其余按两两覆盖抽样；
4. 抽样点必须标注「Pairwise 样本，非穷尽」。
5. 多条件域把每格落成 Cell-ID，并映射至少一个主 Case；安全、越权、资金、不可逆、非法转换和明确拒绝格不得只靠抽样。执行时以 Run/证据回挂 Case，不以 Pairwise 行数、场景数或复验文件数充当执行覆盖。

### 2.4 状态转换矩阵

| 当前态\事件 | 导入 | 分配 | 激活 | 作废 | 重导 |
|---|---|---|---|---|---|
| 未分配 | 重复 | →已分配 | 非法 | →已注销 | 重复 |
| 已分配 | 重复 | 非法 | →激活 | →已注销 | 重复 |
| 已注销 | 允许（新记录） | 非法 | 非法 | 拦截 | 允许（新记录） |

要求：关键档覆盖每个可达「→」、每个「非法/拦截」和终态再操作；标准档至少覆盖主状态路径、全部高风险非法转换及恢复路径，其余抽样列入残余风险。不可达转换标 N/A，不为凑数强造状态。

### 2.5 场景三流

| 流 | 内容 | 最低条数 |
|---|---|---|
| 基本流 | 用户目标一次成功 | 1 |
| 备选流 | 合理分支（如先取消再确认、换筛选） | 标准档目标 ≥2；无意义分支 N/A+理由 |
| 异常流 | 失败/中断/越权/脏数据 | 标准档目标 ≥2；关键档覆盖全部强制触发项 |

异常流来自治理侧异常基线、§2.9 故障清单和变异假设；匹配与 N/A 均留理由，不能凭空编，也不得为满足数量制造重复流。

### 2.6 SBTM 章程模板

```
章程：<目标，一句话>
时间盒：<全域 20min / 块级 10min>
范围：<页面/功能/数据>
风险假设：<本次重点验证的 1 至 2 条>
笔记栏：观察 | 疑问 | 缺陷 | 覆盖（用到哪些功能）
结束：新增 B 点 / 新增缺陷 / 未覆盖项
```

### 2.7 不变量清单（每域 3 至 5 条）

通用：
1. 总数 = 各状态分片之和（含空分片）
2. 成功数 = 实际新增数（导入/批量操作）
3. 幂等重放不改变计数与状态
4. 列表总数 = 筛选结果数 = 导出数据行数
5. 状态变更后，关联字段（时间/操作人/单据号）同步

领域示例：企业「使用号码」= 号码池该企业「激活」数；「申请号码」= 申请订单数量之和。

### 2.8 差分测试

同一份数据在 ≥2 个入口/角色下对比：列表 vs 详情、页面 vs 导出、A 角色 vs B 角色、API 响应 vs UI。差异即缺陷候选（允许的掩码差异除外，需登记规则）。

### 2.9 故障注入清单

| 故障 | 注入方式 | 预期 |
|---|---|---|
| 断网 | 断网/离线模式 | 明确错误、可重试、无半批 |
| 慢网 | 限速 3G | loading 可见、不误判超时 |
| 依赖 5xx | 代理拦截改 500 | 友好提示、不白屏 |
| 接口超时 | 延迟 > 阈值 | 超时提示、任务可重试 |
| 任务中断 | 处理中关闭页面 | 服务端终态一致、无孤儿数据 |
| 重复提交 | 双击/双标签/重放 | 幂等，仅一次生效 |
| 时钟/时区 | 改系统时区 | 时间显示一致 |

### 2.10 可访问性（最低检查项）

1. 键盘可完成主旅程（Tab/Enter/Esc），焦点可见；
2. 表单控件有可访问名称（label/aria-label）；
3. 对比度 ≥4.5:1（正文）；
4. 图片/图标有替代文本（装饰性除外）；
5. a11y 树中关键控件可被读取（快照为空 = 缺陷候选）；
6. 错误提示可被屏幕阅读器播报（role=alert/aria-live）。

不适用时标 N/A 并说明（如纯内部后台可降级，但需产品确认）。

### 2.11 国际化（最低检查项）

时区一致性（页面/导出/消息）、字符编码（中文/emoji 不乱码）、日期格式、金额格式、多语言文案缺失、RTL（如适用）。

### 2.12 Given-When-Then

每条 AC 可改写为：
```
Given <前置条件/数据/角色>
When  <用户操作>
Then  <可观察结果，含具体数值/文案/状态>
```
无法写出 Then 的量化结果 → 标准不合格，先澄清。

### 2.13 缺陷分级（通用）

| 级别 | 判据 |
|---|---|
| P0 | 数据丢失/资金/安全/全模块不可用/不可逆副作用 |
| P1 | 主流程失败、结果错误、敏感数据明文、权限越界 |
| P2 | 一般功能/边界/提示/一致性错误 |
| P3 | 体验/文案/兼容/无障碍小问题 |

### 2.14 缺陷集群与杀虫剂悖论

- 统计每域缺陷密度；密度最高的 2 个域下轮加权重复测；
- 同一路径连续两轮无缺陷时，下轮换数据/换角色/换路径，避免「杀虫剂悖论」；
- 报告写「本轮缺陷集群」与「下轮建议重点」。

### 2.15 无缺陷谬误声明

报告固定段落：本轮未覆盖范围（账号/造数/环境）、残余风险、不适用范围（专项测试）。不得以「全绿」暗示无风险。

### 2.16 变异假设高频 6 条（错误推测法）

开工时写 6 至 10 条（SKILL §1 表 B），执行结束逐条回答：成立 / 不成立 / 无法验证。高频 6 条：

| 假设 | 验证 |
|---|---|
| 空/异常响应不重置前端状态 | 造空 data，看是否残留旧数据 |
| 上限只写文案、后端不校验 | 造上限+1 直接提交 |
| 重复/失败归类混用 | 批内重复 vs 系统重复对比计数 |
| 导出/下载不脱敏 | 导出后逐列比对掩码 |
| 异步无幂等 | 双击/双标签/重放 |
| 权限只藏按钮、接口不校验 | 低权限账号直调接口 |

### 2.17 每域技术巡检（默认 TECH-OBS，不直接形成 UAT 缺陷）

本节输出先记技术观察。只有明确关联到 persona 的真实入口承诺失败，才另立 UAT ❌；无入口影响时可进入专项工程问题，但不得混入 UAT 缺陷数、推翻用户侧失败或替代连续旅程。

| 项 | 检查 | 判据 |
|---|---|---|
| 控制台 | console error | TypeError/未捕获异常记 TECH-OBS；关联入口失败才另立 UAT 缺陷 |
| 网络 | 4xx/5xx | 非预期先记 TECH-OBS/辅证；关联 persona 结果才定 UAT 缺陷 |
| 慢请求 | >2s | 记性能观察，对照阈值 |
| 任务终态 | pending/成功/失败 | 失败必须有原因 |
| 数据残留 | 操作前后计数 | 与基线对账 |
| 可访问性 | 键盘、焦点、可访问名称、a11y 树 | 先记 TECH-OBS；影响 persona 操作/读屏时立 UAT 缺陷；控件按稳定 control_id 做差集 |
| 国际化 | 时区、编码、日期、金额 | 用户可见不一致才立 UAT 缺陷，否则 TECH-OBS |
| 故障注入 | 断网、慢网、依赖 5xx、超时、中断、重复提交 | 按风险裁剪并注明 |
| 日志增速 | 日志行数/小时 vs 本轮基线 | 暴涨（超基线 3 倍以上）即异常信号，必须归因到具体来源——高频写入型污染（幽灵轮询/重试风暴）在未影响功能前就会在此现形 |
| 错误码计数 | 4xx/5xx 按（状态码+URL）成组计数 | 先记 TECH-OBS；**同码同 URL 高频重复=轮询放大特征**（固定间隔、永不消失），必追根因并关联用户影响 |
| 重复请求模式 | 同 URL 高频重复扫描 | 幽灵映射/死循环/测试注入的识别特征：同 URL 以固定短周期重复且无进展=必查项，与「慢请求」互补（慢是单次贵，重复是无效多） |

## 3 挂接方式

1. 任务书生成时：每域过一遍方法适用性；有多条件才建判定表，有状态实体才建状态矩阵，有可量化业务规则才建不变量；不适用写 N/A+理由。
2. 执行台账增加列：`方法`（BVA/判定表/状态/不变量/差分/故障注入/SBTM）与风险档。
3. 报告输出：方法覆盖回执、不变量对账表、缺陷集群、未覆盖声明。
4. 覆盖率体检：只检查「适用方法是否有落点、计划点是否执行」；缺 N/A 理由或适用方法空洞才判方法覆盖不足。
