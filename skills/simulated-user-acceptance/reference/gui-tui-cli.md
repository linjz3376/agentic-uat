# 人类界面与真实机器入口

> 配套 SUA §0「验收身份、入口与执行模式」。拟人关注的是**谁、为何、经何真实入口、看到什么结果**，不是只有鼠标和页面才算拟人。

## 1 交互形态

| 形态 | 人类 persona 的真实用法 | 主证 |
|---|---|---|
| GUI | 看屏→点击/键入→读渲染结果 | 判定时截图或 DOM |
| TUI | 持续终端会话→键盘导航→读屏 | 终端读屏/输出快照 |
| 人类 CLI | 用户按业务目标逐条输入命令、读 stdout/stderr、处理后续状态 | 命令原文+输出+最终用户结果 |
| 人类 API | 产品明确把 API 作为该人类技术用户的日常入口，用户理解并检查请求/响应 | 调用方可见请求/响应+最终业务结果 |
| 机器调用 | 产品明确交付的机器/外部系统按公开契约调用 | 契约响应/错误码/字段/调用方状态 |

## 2 入口标识互斥

- `[UI]`：所有**人类 persona** 的产品交互界面，包括 GUI、TUI、人类日常 CLI/API。不得因「管理员」「运维」「开发者」「习惯终端」改判 MACHINE。
- `[MACHINE]`：仅限产品明确交付的机器/外部系统调用方，使用自己的凭据与公开契约。「没有 UI」「只有 CLI」「管理员身份」都不是充分条件。
- `[DOC]`：不参与产品 AC，只做独立覆盖审计；纯 DOC 不得称 UAT 或出 UAT FINAL。

内部接口、DB、日志和源码不是人类或机器 persona 的产品入口，只能作预声明辅证或 TECH-OBS。禁止借用管理员 Token、内部接口或仅 HTTP 200 冒充真实调用方结果。

## 3 人机双入口

同一能力同时交付人类界面与机器入口时：

- 人类旅程判界面呈现、内容、操作反馈、恢复和最终业务结果；
- 机器旅程判调用方契约、鉴权、错误语义、关键字段、状态迁移和重试幂等；
- 两者都需落判，但互不替代。机器契约成功不得推翻人类界面失败，反之亦然。
- MACHINE 有状态变更语义时才要求预期可观察副作用；纯只读契约不得为取证另造副作用。

## 4 拟人连续性

GUI/TUI/CLI/API 的人类旅程都必须有：动机→起点→连续操作→必要交接→最终用户结果。打开页面、执行单条命令或调用一次接口只是步骤，不等于端到端目标完成。

- GUI 焦点/坐标/窗口纪律、TUI 读屏、CLI 逐命令输入和 API 调用方回读均属于真实入口操作。
- 技术信号只作 TECH-OBS；未关联 persona 的入口侧承诺失败，不单独形成 UAT 缺陷。
- 入口标错→修正并记偏离；载体不可用→最小作用域阻塞，其他独立旅程继续，不得静默换内部接口。
