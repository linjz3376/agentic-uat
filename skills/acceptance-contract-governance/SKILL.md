# 验收契约与测试任务指令文档治理（Acceptance Contract Governance）

## Overview

**技能目标**：**高覆盖面的测试验证点执行指令**——
- **高覆盖面** = ① **test basis 穷尽**（硬闸）：四活源推导落到需求、路由/入口、深度维度三份可点名清单；② **行为空间按风险有界设计**：生成期为每域/AC 标关键、标准、探索档，等价类、Pairwise、golden set 与代表抽样均合法，未执行候选须进残余风险，禁止以「没测完所有输入组合」返工或虚报；③ **覆盖公式只统一口径，不设产品质量及格线**——需求归宿分布与三度量唯一公式源为 `references/coverage-metrics.md`；UI 主证 100% 只是证据完整性闸，不是产品全绿指标。禁以历史任务书/契约为基底；
- **测试验证点** = AC-ID 化、可判定、每点带真实入口。产品 AC 仅允许 `[UI]`（人类界面）或 `[MACHINE]`（真实机器调用方）；纯对账使用独立 DOC 审计表，不进 AC 主表、场景矩阵、需求验证分子或 UAT 收官。
- **执行指令** = 自包含单文档：冻结本轮判据、所选执行模式、授权、报告和产物规则；SINGLE_WRITER 默认包含共享状态机、逻辑四态、长窗收判与最小断点，PARALLEL_UNATTENDED 仅因真实并行/接管而加租约/CAS/fencing/分片恢复契约。出处只作静态溯源，运行时不热切换。
- 项目安全红线与操作者显式授权不得放宽；版本演进历史见 references/changelog.md，正文不内联版本标签、不作过程叙述。

**双模式技能**：
- **生成模式（主）**：把「重点测试某功能」的需求变成**一份自包含的可执行指令文档**——交付物只有它，拿到就能跑，执行 agent 无需再追问。
- **治理模式（辅）**：对既有验收契约（常驻文档）体检、清历史污染、做 29119-3 三件套拆分。

**形态原则（复用次数决定形态）**：常驻主契约服务多轮 → 设计/规程/数据三层分离防漂移；块级任务指令服务一轮 → 自包含单文档降低执行摩擦。任务书里可复用的部分（新端点/探针/AI 判据条目）执行后回写 fixtures/playbooks，成熟的新验收点递单回流主契约。

## 核心定位：为「模拟用户验证」而生

本技能的一切产出服务于一个目标——**让执行者以真实用户的身份完成业务旅程，并作出用户视角的判定**。验收点表是审计骨架，不是执行形态；执行形态是**用户场景**：谁在什么动机下走什么旅程，每一步看什么、期待什么、怎样算受阻。

三条灵魂判据（每份交付物自答）：
1. 执行者读完知道「我是谁、我要干什么、完成长什么样」（角色+业务目标+旅程）
2. 每个判定都能回答「真实用户此刻会看到什么、会怎样反应」
3. 缺陷描述用用户语言（「我收藏的知识找不到了」）而非系统语言（「缓存未失效」）

**UAT 身份硬闸**：任务书至少一条真实 persona 产品业务旅程，含动机、起点、连续基本流、交接和最终入口结果。DOC-only 只能出覆盖审计，不能称 UAT 或出 UAT FINAL。缺陷摘要必须写 persona+目标+真实入口+实际/预期可见结果，并由执行侧自检。

**机器身份也是用户**：仅限产品明确交付的机器/外部系统调用方，使用自身凭据和公开契约。人类管理员/运维/开发者以 CLI/API 为日常入口时仍是 `[UI]` 人类界面，按终端/调用方可见结果拟人判定，不得借 MACHINE 绕过。

## When to Use

- 用户说「重点测 XX 功能」「给 XX 安排一个测试任务」「出一份 XX 的验收/测试指令」「出任务书/测试计划」——范围词路由：模块名→块级模板；「全项目/全域/跨模块/全流程/全面深度测一遍」→全域轮模板（project-instruction.md）。拿不准时按全域轮处理，并在回执中说明范围判断
- 用户提供 PRD 章节/口述标准，要求转成可执行的验收点
- 用户问「N 个验收点是否已全面覆盖/够不够全」→ 触发完整性背书规程（references/source-reconciliation.md），穷举源头需求行逐条归类后才可下结论
- 用户点名**验收契约**（常驻文档）要求治理：体检、清历史状态、按 29119-3 拆分、迁移到新项目——指令须含「验收契约」锚，纯「清理/评审/审计 XX」无此锚不归本技能

**不用**：本技能负责生成任务指令，不负责实际执行。执行者按任务书内嵌手册跨平台执行；`simulated-user-acceptance` 可作为通用执行指南（若可用），不是执行前提。任务/缺陷闭环、无人轮审计和自由探索可使用相应流程；这些流程或技能不可用时，按任务书内嵌的自包含规程继续，不因本机缺少特定技能而阻塞。

## 生成模式（主）

### E2E 手工优先原则（功能测试的默认姿态）
默认验证姿态 = **模拟真实用户的端到端测试**：从该 persona 实际可用的入口出发完成业务旅程，按其可观察结果判定。五条规则：
1. **可机判 ≠ 必须脚本化**——判据必须能被人类在真实界面（页面/终端/调用方视图）观察，或按真实机器入口契约判定（阈值类用户可掐表：≤3s/≤2s）；只有当判据**本质不可由该入口观测**（审计字段、索引时延、孤儿对象、并发计数）时，才允许 DB/日志/内部接口取证，且只能定位为辅证，**不替代入口侧判定**。
2. 验收点表「回显验证」列每点必做；「数据源验证」列是可选辅证列，不是每点必做。
3. **人工判定是合法出口不是偷懒**——主观项显式标「人工判定」并给核对要点；这里的“人工”指执行者按页面作语义判断，不自动等于真人介入，确需真人的必须预登记，禁止用 DB 反推页面通过。
4. 禁止「脚本绿 = 功能过」——接口 200 只证明可达，不等于契约正确、更不等于用户旅程通过。
5. **入口二分（取代「API 一律为辅证」的旧口径）**：
   - 产品 AC 的主入口只有两种：`[UI]` 人类交互界面（GUI/TUI/人类日常 CLI/API），或 `[MACHINE]` 真实机器/外部系统的产品契约入口。
   - `[MACHINE]` 只有一个合法条件：persona 是产品明确交付的机器/外部系统调用方，使用自身凭据与公开契约。「没有 UI」「管理员/运维身份」「CLI 是习惯入口」均不充分。
   - **persona 是人 → 必须 `[UI]`**；若其日常主界面是 GUI 且 GUI 可达，必须真实 GUI 事件完成旅程，TUI/CLI/API 不得为自动化方便替代。只有替代界面确为该 persona 日常真实入口且匹配业务目标时才合法。人机双入口分别判定，不得互相替代。
   - `[MACHINE]` 点按 L1/L2/L3 正常判定、**不标「辅证」**，但必须写契约断言：状态码、业务错误码、鉴权结果、关键字段；有状态变更语义时另写幂等键和预期可观察副作用，纯只读契约不得为取证另造副作用。
   - **管理端入口按 persona 判定**：人类管理员/运维走 `[UI]` 人类界面；只有产品明确交付的管理代理/运维自动化客户端才走 `[MACHINE]`。人工业务触发与机器自动触发分开标注，不得混算。
   - **入口存在性侦察优先序**：判定某能力是否具备机器入口，按 ①**契约侦察**（OpenAPI/Swagger 文档、网关路由注册、服务目录、后端路由装饰器/Handler 映射）→ ②**调用链路侦察**（前端请求封装层、代理/网关转发配置、浏览器 DevTools 或 HAR 抓包精读的接口调用）→ ③**通道结论**（仍不可得时按三选一落结论：通道不存在 / 存在但不可用+原因 / 存在但未授权）的顺序取证。前后端分离只是 API-first（契约先行）交付模式的常见形态，**不是接口存在的证据**；管理端页面可观测的写操作至多算「存在性高概率线索」，须经 ①或 ②实证后方可计为有效执行入口。
   - **DOC 独立审计**：覆盖对账/文档核对放独立审计表，使用 AUDIT-ID，不用 AC-ID，不挂场景、不计需求验证分子、不参与 UAT 三态；纯 DOC 只出 coverage-audit 报告。
   - 内部接口、DB、日志、源码**永远不是入口**，只能进「辅证」列；`[AUX]` 不允许作为任何验收点的主入口。
   - 禁止用管理员内部接口冒充普通用户入口；机器身份必须用它自己的凭据，不得借用管理员 Token 代判。

### 场景生成力闸

**机械闸（缺一即返工）：**

1. **场景八要素+连续性**：每个 S-ID 有 persona/动机/业务目标/入口/基本流/备选流/异常流/交接，并写起止状态与最终用户结果；基本流必有，标准档备选/异常各 2 条为设计目标，关键档强制异常不漏，无意义分支 N/A+可核理由。
2. **场景-AC 矩阵**：每个产品 AC 挂到真实旅程具体步骤，每个非探索场景至少一个 AC；矩阵只证明审计归属，不证明旅程完成。禁止 G-DOM/管理员场景默认承接「该域全部 AC」；域内按不同业务目标拆分，共享旅程须证明共同动机与连续基本流。
3. **handoff 矩阵**：跨角色/跨块场景必须写 `从 S-ID/角色 → 到 S-ID/角色 | 对象/状态 | 入口 | 期望`；没有交接记录=场景没走完。
4. **执行顺序**：任务书 §6 必须写“按 S1→Sn 场景执行（⛔/高风险场景优先），场景内基本流→备选流→异常流；域顺序只做 AC 回归”；写“按域顺序执行”=场景降级，返工。
5. **人类界面步骤脚本**：GUI 主界面可达时必须真实点击/逐键输入/选择/键盘/对话框，不得用 CLI/API 图省事；GUI 写实际控件/对话框/保存回显；TUI/CLI 写逐键或逐命令输入与终端读屏；人类 API 写调用方请求/响应及最终业务结果。只写「填表保存/调用接口」且无入口结果=不可执行。
6. **G0 模板**：全域 20min/块级 10min；四栏笔记（观察/疑问/缺陷/覆盖）；产出新增 B 点/缺陷/未覆盖；G0 不是 checkbox，是执行场景。

**场景点遗漏的高频区**（生成时逐条核）：角色交接（导入→复核→归档→抽样→审计）、失败恢复（识别失败→人工复核→重传）、审批回退（manifest 404→手工归档/恢复）、抽样闭环（计划→任务→打标→问题/通过→统计）、跨块追踪（任务→发票→目录→修改记录/审计）、双角色隔离（管理员 vs 普通用户 vs 审计只读）。

### 前置闸门：目标项目确认与源头新鲜度核验

- **目标必须明确（多项目并存时禁止凭上下文默认值拍板）**：生成前先枚举项目区候选（如 `ls <项目区>/`；PowerShell 等价 `Get-ChildItem <项目区>`），用任务性质信号逐项匹配：① 用户指令/上下文是否显式点名 ② 项目内是否有需求源头文档（PRD/设计）③ 是否有测试基建与活跃台账（tests/ 树/缺陷台账）④ 本机上下文文件锚定的质量/测试归属域。**唯一匹配→继续；≥2 个候选同时匹配且用户未点名→按澄清问题协议回问（业务语言+≤3 选项+写明默认项），禁止静默沿用会话默认值**——「我一直做这个项目」不是判据，是惰性。产出文档头部写明项目名与来源文档名。
- **新鲜度是实测值不是默认值**：源头文档（PRD/设计）以版本控制为准——生成前 `git fetch` + 核对 `HEAD..origin/<主分支>` 落后提交数与源头文档 diff（或等效 VCS 操作）；落后→先同步到最新，或在文档头部声明「基于 <commit 短号/日期> 快照」；无版本控制的源头→记文件 mtime 并写入头部声明。判据同判定锚纪律：新鲜度每轮当场核验，禁止凭「上次拉过」推定。
- 无 N/A：拉不到远端（离线）→头部声明离线快照日期后继续，报告注明。

### 造数通道盘点（先于一切「无法验证」结论）

生成与执行都必须在写点、判 BLOCKED 之前，盘点**能进入被测系统的通道**，并随交付附一张表：

| 能力 | 通道（页面 / API / CLI / 客户端） | 可用性 | 授权与范围 |
|---|---|---|---|
| <如：造归档发票> | `POST /api/v1/import-tasks/{id}/historical-commit` | 可用 / 不存在 / 不可用（原因） | <本轮是否获准> |

判据：
- 涉及入口存在性/可达性的 `⏭️`、`UNREACHABLE`、`UNAUTHORIZED` 必须给三选一：通道不存在/存在但不可用+原因/存在但未授权。BUDGET_EXHAUSTED、OBSERVABILITY_BLOCKED、DEFERRED、OMITTED 和纯 DOC 不适用项按各自证明，不伪造通道结论。
- **禁止把「我没找到」写成 BLOCKED**——写接口、CLI、页面入口都要主动枚举（路由装饰器、CLI 命令、前端导航），而不是凭印象。
- **造数通道 ≠ 判定通道**：用 API/CLI 准备数据合法，但造数动作的返回码不得作为该点 PASS 依据；造数必须登记前缀、归属与清场债务。
- 造数通道需要改动远端配置或重启时，视为**未授权**，不得自行开启；只能记为待授权或改走本机隔离栈。

### 自主执行优先设计闸（执行形态基线）

任务书的默认执行者 = **无人值守的 AI agent**（自主执行是设计目标，不是执行期的即兴发挥）。落笔前必须过这道闸：

1. **通道优先序（E2E 拟人操作为核心）**：同一验收目标存在多种执行通道时，按 persona 的真实入口选择，不作全局 UI 优先；按「**①真实入口拟人自动化（核心）**——按被测产品的真实用户入口选型驱动通道并同步操作之：浏览器类→DOM/Playwright 自动化；桌面客户端类（聊天/邮件/办公等）→坐标点击/键入/剪贴板粘贴/剪贴板回读/判定时截图自查（Chromium/自绘 UIA 裸树时依然成立）；其他入口以此类推。**拟人四要素恒定**：真实事件操作、动作后验证可观察变化、判定时留证、默认无人值守；仅预登记的平台物理强制项可使用真人窗口，未预配真人不得空等。PC QQ 只是聊天客户端类的一个实例，非本原则的范围边界。**②真实机器/外部系统的产品公开契约入口=MACHINE 主证**；测试注入端子、平台模拟器、内部诊断接口只作造数/辅证/TECH-OBS③真人操作（仅平台物理强制项，如平台只接受真实客户端回调的特定交互）」排序选点；平台类约束必须在生成期用一条端到端探针**实证或证伪**，禁止把关键假设留给执行期首发现——平台类假设错误是驱动器返工与批量人机中断的高发根因。驱动器实现属项目侧资产，技能本体零实例（可移植红线）。
2. **执行模式、授权与人机协同前置**：默认 SINGLE_WRITER，只有真实并行写者/外部接管才选 PARALLEL_UNATTENDED；单写者始终内联逻辑四态、长窗收判、超时和最小断点，不写租约/CAS/多写者接管。任务书 §2 内嵌 SUA 授权快照和本轮清单，逐项列目标环境、账号/角色、对象、数据前缀、测试写入/消息、报告根、跨轮台账、清场、优雅重启、外部接收方和预算。操作者当轮明确签署清单后，预授权内+可逆动作连续执行；**禁止命令即签、沉默即 GO**，无答复只放行安全只读子集。裸杀永远禁止；secrets 仅允许提供方受控注入，代理不得读取、打印、复制、落盘、改写或删除密钥源。发布发版、共享数据删除、目录外写等治理动作须逐项显式授权；优雅重启须具名对象+窗口+在途检查+恢复方式。确需真人的点进入开局人机批次表，**不超过两个时点是规划目标，不是全轮停止闸**；运行中出现不可预见依赖时按 SUA「迟发依赖」局部挂起、聚合通知并继续独立项，只有 test basis/范围/判据改变才回生成侧修订，禁止一律打回重做。
3. **载体风险预登记**：生成期确认执行载体形态并用探针验证；不可达点优先重设计该 persona 的其他合法真实入口，或预写局部 BLOCKED/降级预案。生成期只登记通道风险和证据，**不得预写本轮 UNREACHABLE/⏭️ 执行结论**；执行期按当轮复核与有限努力证明落判，其他 READY 项继续。
4. **环境还手预判**：被测系统带自动拉起/看门狗/单实例锁时，任务书必须预写「测试替身接管规程」（停用谁、抢锁失败重试几次、如何复原），禁止执行期 improvising；**拟人自动化额外要求**：操作者共享桌面时必须预写「清场窗口或独立会话」二选一并获操作者确认——共享桌面下坐标自动化与真人操作相撞是实测高频事故。

5. **资源依赖自助化分级**：依赖操作者资源的验收前置（重启窗/第二账号/隔离栈/停机）禁止裸进人机批次表——先过自助化分级：**可自助项必须写成自助化设计**（隔离栈=本机起独立引擎实例、重启窗=空闲探测+自动选窗+预授权消费），不可自助项才准入窗口包且必附自助化已穷尽举证。判定口径：窗口包是「自助化尽头的容器」，不是「等 owner 的容器」。SINGLE_WRITER 始终内联一次性收判/触发器、解除条件、`resumeAfter`、超时和最小断点；长窗在同一任务与授权内原地 RUNNING⇄WAITING，不另出书、不重复请示、不升级并行。无触发能力或超时→转有归因 BLOCKED、继续 READY 或出 INTERIM。PARALLEL_UNATTENDED 只在实际并行/接管时另加租约、CAS、fencing、分片归并和触发器迁移。禁止安静等待和常驻轮询。触发器只要求「一次性时间/事件注入或等效机制」，不绑定具体运行时。

**删除阀登记**：①不替代「E2E 手工优先原则」——该原则管**判定姿态**（以用户视角与可观察结果判），本闸管**执行形态设计**（谁来按、怎么按），二者正交；②失效条件：当目标产品普遍提供官方测试注入通道成为生态惯例、且平台模拟驱动器可由 fixtures 标准化复用时，本闸第 1 条的通道优先序部分进退役评审。

### 素材自挖原则（用户只出意图）
生成任务书所需的现状素材由 agent 自己挖，**不向用户要清单**：「测什么/不测什么」「前端路由有哪些」「端点有哪些」都是 agent 可自挖的事实——读 PRD/设计文档、缺陷台账，实测页面路由与后端端点（测试侧可读范围见下方目录白名单）。用户只给意图（模块名+「更全面/重点测 X」类方向），理解诉求→挖素材→生成 prompt→产出文档全归 agent，过程中不向用户回填选择题。只有挖不到且影响判据真值的口径缺失才回问；挖得到的一律不问——把自挖清单当问题丢回用户=把 agent 本职推回给用户。

**生成期素材目录白名单（机械规矩）**：生成任务书时可读的测试侧内容**仅限缺陷台账镜像 + 缺陷队列表（bugQueue）**——缺陷是实测锤出的一手事实，四活源之一。台账镜像**动态定位**：扫描 `<项目>/tests/reports/` 下现存的缺陷台账文件（按 defect/tracker/缺陷 语义识别，一份为准；多份并存须先对账合并再引用，禁止凭文件名猜）。`tests/plans/`（历史任务书）与 `<项目>/tests/reports/` 下的执行产物目录（`<日期>-*/` 形态，动态识别而非枚举名单）**目录级禁读**——派生产物不因其在 tests/ 下就变成事实源。判据一句话：内容属于「谁的实测事实」还是「哪次生成的说法」；但执行按目录一刀切，不按性质个案判断（性质判断留解释口子）。**夹具例外**：`<项目>/tests/fixtures/` 下的数据/夹具/golden 文件**可读**——夹具是执行资产与实测沉淀物，不是口径基底，复用不构成基底依赖；AI/LLM 类判据生成前**必查该目录现有 golden set**：存在即复用其断言结构写进验收点（机判），未建才降级「人工判定」并显式注明「golden set 未建」。fixtures 目录内的任务书/报告/契约类派生文档仍按派生产物禁读。**可移植红线：技能本体与产出文档零实例残留——项目名/文件名/目录名/主机/账号/ID 一律占位符或动态扫描，实例专有命名只准出现在本机上下文文件，不进技能、不进任务书（changelog 历史区豁免：旧条目中的路径/邮箱仅作留痕，不作现行口径）。**

**生成基底=四活源全新生成，禁以派生产物为基底**：每版任务书从 ① PRD/设计文档横切（**覆盖范围唯一来源**）② 缺陷台账 ③ 现行 UI/端点侦察 ④ 十一维加钻 **重新生成**；旧版任务书/历史契约=派生口径，只留痕不作基底。派生叠派生=误差复利（两次实证见 references/pitfalls.md「以历史任务书为基底」条）。**历史参考白名单**：对历史轮次唯一合法引用=缺陷台账条目的 ①**修复状态**（⛔ 放行/回归判定）②**首次发现时间**（龄期/上下文）③**编号**（⛔ 挂链/复验锚）。禁止以历史缺陷内容或历史缺陷分布做设计输入（加钻只由 PRD+十一维+现行侦察推导）。历史任务书/历史报告/历史证据目录级禁读（生成期已有，**执行期同禁**：本轮判定只看本轮任务书+本轮实测）。**每轮全部重新执行**。

**挖掘顺序=需求源头优先**：①动态定位 PRD/设计/用户明确承诺并摘全需求 ②与现行 UI/端点/实现做双向差异扫描，代码只证明实现/入口，不自动成为需求或预期 ③两需求源冲突标 ⏸️并实测。一次性任务书生成不得读取历史契约/任务书做点集对账；既有文档差集只允许在独立治理模式处理。规程全文见 `references/source-reconciliation.md`，头部写来源、实现差异和冲突摘要。**无源头文档分支（降级路径，基底红线不变）**：动态扫描无果→①现行 UI/端点侦察升为主源，用户当轮明确承诺与可点名行业惯例/合理期待补源，历史任务书/契约/报告仍禁读 ②头部声明「无 PRD 基线·覆盖口径降级」，需求分母=侦察+明确承诺+惯例条目，缺陷台账只作复验锚不进需求分母 ③禁止无声明裸跑。规程全文见 source-reconciliation.md「无源头文档降级规程」。

**澄清问题协议（向用户回问的纪律）**：默认用户非技术、只说得出意图，回问是最后的口子不是工作方式——**三条件同时满足才问**：①口径影响判据真值（不问会产生错误 PASS/FAIL）②PRD/设计/实测/台账全部自挖无果 ③答案无法靠执行期实测记录兜底。怎么问：业务语言一句话（禁术语）+ 选项 ≤3 个 + **默认项写明「不答则按 X 执行」**；一轮最多 3 问；问完立即继续不停等。示范（恢复权限双源冲突的正确问法）：「删掉的文档谁来恢复？A 只有管理员 B 作者 30 天内自己也能 C 定不了就两边都记录、暂不定谁对（默认 C）」——错误示范：「PRD V2 §3 与契约 AC-02-005 口径冲突，请裁定」（术语堆叠=把工作推回给用户）。

### 工作流
1. **场景建模**（灵魂步骤，先于一切）：产出 S-ID 八要素、场景-AC 矩阵和 handoff 矩阵；全部验收点挂靠至少一个场景。基本流必有；标准档以备选/异常各 2 条为设计目标，关键档覆盖全部强制异常，确无意义分支写 N/A+可核理由，禁止重复凑数。**异常流来源=异常基线库强制项+建议匹配项+表 B 特异项；异常状态与恢复成对。** 全域按真实业务目标拆分域内与跨块旅程，禁止域批场景吞并全部 AC；纯技术检查另列 TECH-OBS，DOC 对账独立。
2. **需求解析**：PRD 章节 / 用户口述 / 端点探测 → 逐条可核验条件；有歧义当场澄清，不猜。
3. **覆盖依据表先行（scope-first）**：每域一行「域→需求出处→条目类型(PRODUCT/AUDIT/MIXED)→风险档→计划点数→来源类别→动作/墙钟预算」；AUDIT 不进产品四桶，MIXED 拆产品 AC 与 AUDIT 链接；有 PRD 时覆盖认 PRD 出处，无 PRD 时认现行侦察+用户口述+可点名惯例，历史契约永不作基底。scope 与预算锁定后才写点，任何「已有块书所以少写」均无效。**路由→验收点全覆盖（全域轮强制）**：每条路由/入口有 AC 或显式 ⏭️/N/A+理由；风险抽样只裁行为组合，不得让路由和页面静默缺席。
4. **深度设计（风险有界）**：走十一维检查表，D1 功能正确性永远先行；各维有点或 N/A+理由。D1 分档与负向 30% 是 P2 质量基线，低于时写偏离原因，不得同时称「硬性不许交付」。D2 先产候选再按关键/标准/探索档选择本轮计划；共享字段跨 AC 去重，条件达到 4 个时以 Pairwise+高风险组合替代指数级全量。安全/越权/资金/不可逆项不得抽样降格。负向必须挂正向基线，无基线项按 ⏭️+通道结论处理并剔除分母。覆盖表生成时回填真实 AC-ID，留白=返工；交付附风险档、计划/候选分母、预算和残余风险。
5. **验收点推导**：列表成表——每点含 AC-ID + 入口标识 + 操作（可直接执行的命令/路径）｜预期（可机判）｜回显验证｜数据源验证（可选辅证）+ 门槛标注（模板见 templates/task-instruction.md §3 列结构，其含标准「向（正/负）」列构成七列——全域轮强制采用，负向占比从人工点数变可机跑；机跑命令见 references/self-check-gates.md；窄域小任务可省「向」列维持六列，省略时回执的负向占比按人工点数并注明）。**产品 AC 操作列首令牌只能是 `[UI]` 或 `[MACHINE]`**，逐行互斥且无缺省；DOC 对账移独立 AUDIT 表。操作列落笔前先做 **入口实况侦察**：UI 点逐个确认引用的页面/按钮/控件存在、路由可达、文案口径（如大小限制、权限提示）与预期一致；GUI 有状态写点按适用性写 confirm/alert/prompt 与保存后回显；TUI/CLI 写终端输入/输出，人类 API 写调用方请求/响应和最终业务结果；纯只读点不强制对话框或保存回显。机器入口点确认端点/命令存在、鉴权、错误码集合；有状态变更时确认幂等要求——端点 200 只证明后端在，不证明用户够得着，也不证明契约正确。
6. **判据量化**：预期里的每个模糊词（「明确/正常/合理」）必须进判据表换成量化阈值，或显式标注「人工判定」；AI/LLM 类问题必须 golden set 条目（结构见 `references/ac-id-rules.md`）。
7. **AC-ID 分配**：已有验收域续号；全新功能开新域 `AC-<域>-###`；规则见 `references/ac-id-rules.md`。
8. **门槛标注**：依赖未修缺陷的验收点标 ⛔ 并逐条链接台账条目（缺陷台账为单一事实源，状态不内嵌）；探索性无实现标 ⏭️；两源口径冲突挂起待裁定标 ⏸️（⏸️ 定义=已执行有观察、标准冲突待裁定，与 SUA「缺陷、终态与有限归因」及 coverage-metrics 口径一致）。台账登记时 **P2 及以上缺陷必须附 test basis 条款引用**，缺失引用降 P3——引用是定级输入，不是事后补注。**台账→验收点全映射闭环（强制）**：生成收尾时把台账全部在管条目逐条对到 ≥1 个验收点（⛔ 挂链 / 复验锚 / 显式 N/A+无 UI 面理由），映射表随交付——台账是实锤失效模式清单，漏挂一条=放弃一次最便宜的深度来源。
9. **环境前置与所选执行模式成段**：可达/健康/账号/依赖映射受影响旅程，只有全部剩余项受影响或安全/证据整体失真才 GLOBAL_NO_GO。所有任务书内嵌 persona 卡、连续旅程、用户判据、授权、预算和报告规范；SINGLE_WRITER 默认加共享状态机、逻辑四态、长窗收判和最小断点；PARALLEL_UNATTENDED 仅实际并行/接管时加写者租约、CAS、fencing、分片归并与恢复契约。环境前置写预期最高报告状态及重估规则。
10. **完成准则 checklist**：本轮运行状态达到 CLOSED=每个 AC 有合法终态或有归因的 BLOCKED+判定登记完成+报告已签发。❌/PARTIAL/⏸️ 可结束本轮；缺陷修复、风险接受、经验回灌是后续独立闭环，不得作为停止或签发报告的前置。
11. **落盘**：`<项目>/tests/plans/<topic>-uat-<date>.md`（骨架见 `templates/task-instruction.md`；全项目/跨块范围用 `templates/project-instruction.md`——全域书**自带各域深度内联**（范围与深度都只由 PRD+十一维推导；「另派块级深化任务书」是全域书之后的增量深化，不是替代、更不是减点理由），在深度内联之上再做它独有的加钻：跨块集成旅程+块间缝隙查漏+全域覆盖对账）。

### 自包含铁律（所有一次性任务书，凌驾六标准之上）
执行所需规范与操作必须全部内联，但**仅限所选执行模式**：persona/连续旅程/判据/授权/用户报告/预算/共享状态机/逻辑四态/长窗收判/最小断点始终内联；租约、CAS、fencing、分片归并和接管仅 PARALLEL_UNATTENDED 内联。生成时读取 SUA 当前规范并固化快照，附静态出处和内容哈希；`见契约`、`以某版本为准`、`执行期以当前版本为准`、`全表见外部文件`一律禁止。运行时规范外部依赖=0；业务事实源仅允许缺陷台账和密钥提供方：台账不可达用头部 dated snapshot，密钥注入不可用按角色局部阻塞，禁止猜测。宿主安全红线更严时从严；其他外部版本差异只记录，不热切换。差异影响判据真值时相关 AC 实测后判 ⏸️，不影响项继续，无需等待外部裁定才出报告。

**任意 Agent 可执行性（设计基线，凌驾一切）**：交付文档必须内嵌「执行者手册」——如何代入 persona、用什么入口（浏览器页面 / API / CLI）、逐步执行规程、判定纪律、外部依赖降级路径。执行方**无需拥有任何特定技能、记忆或上下文**，任意 AI agent 拿到文档即可开始模拟用户验证。文档中「交给某某技能执行」一类路由语只是本机调度便利，不是文档的依赖；执行方法本身必须在文档内自含。

### 交付物 = 一份指令文档，六条主标准 + 补充标准 7/8/9（详见 `references/executable-standards.md`）
1. 每个验收点有稳定 AC-ID
2. 操作列可直接执行（真实命令/路径，探过可达），产品 AC 首令牌为 `[UI]` 或 `[MACHINE]`；DOC 审计不进 AC 表
3. 预期列可机判（**人类能在真实界面判定（页面/终端/调用方视图）**，或按机器入口契约断言：状态码/错误码/鉴权/字段；有状态变更时另核幂等/副作用；主观项显式「人工判定」+核对要点）
4. 环境前置成段（GO 才开工），含造数通道结论
5. ⛔ 门槛逐条链接台账
6. 完成准则 checklist 式

缺一条即返工——交付前逐条自验。

### 交付后
指令文档由执行者按内嵌手册执行；`simulated-user-acceptance` 等通用指南可辅助但不是依赖。执行中任务卡与缺陷流程遵循任务书自带规程；可复用产物回写执行资产；新验收点交维护人。**本技能交付即完成，不跟执行。**

**生成单≠执行单**：用户要「prompt/任务书」时只生成不执行——生成即执行会让未经评审的深度直接固化进执行。派单 prompt 只写纪律/授权/红线，执行知识全在任务书内自包含（防双事实源漂移）；凭据永不入 prompt。**交付回执带七项数字摘要**：总点数/十一维完备（有无 N/A）/D1 占比/负向占比/场景数（含基本/备选/异常流计数）/UI 点数与 UI 主证要求/**需求归宿分布（覆盖/⏭️/⏸️/纯未覆盖四桶机验数，纯未覆盖必须为 0，口径见 references/coverage-metrics.md）**，外加新增点来源统计、**入口分布（`[UI]`/`[MACHINE]`）**、关键旅程数及完成/失败/受阻结论数；DOC 审计数另列但不计 AC/需求分子；BLOCKED 点另报通道结论分布（不存在/不可用/未授权）。占比低于基线时如实标注偏离原因，不粉饰数字。**回执只讲本次交付物本身**：用户问「多少点」就直接报本次任务书的数——不主动给跨文件汇总、版本演进对比、历史计数（历史是留痕不是叙事素材，用户问差异时才给）；来源统计只描述本次各点的出处类别，不扯旧版点数变化。

**收官闸（Final-Report-Gate）**：UAT 身份前置=至少一条真实 persona 产品旅程有完成/失败/受阻结论；DOC 不进 AC/需求分子/三态。所有模式共同前置=每个计划产品 AC 为 DONE 或六类 BLOCKED；SINGLE_WRITER 另核逻辑四态已落 execution-log、无待续/可执行独立项且不创建并行写者契约，PARALLEL_UNATTENDED 才核 READY=0、WAITING=0、DONE+BLOCKED=产品 AC 总数。顺序判定：①任一入口 PARTIAL、OMITTED/BUDGET_EXHAUSTED、主证/计划产物缺口、⏸️ 缺待定性/默认建议、P=O+S+G 不成立、S/G 缺稳定 ID/证据/合法映射→INTERIM；②不满足①且存在 BLOCKED/未裁定 ⏸️/S/G，全部 BLOCKED 为 UNREACHABLE/UNAUTHORIZED/OBSERVABILITY_BLOCKED 或获接受 DEFERRED、⏸️ 要件齐、S/G 有同类合法映射→FINAL-WITH-GAPS；③否则 BLOCKED=0、PARTIAL=0、未裁定 ⏸️=0、UI PASS=0 时 N/A+理由，UI PASS>0 时对应主证 100%、S+G=0 且 O=P→FINAL。❌ 不阻止 FINAL；自主全项无缺口可 FINAL，无缺口不得 WITH-GAPS。`final-report.md` 承载 FINAL/WITH-GAPS，禁止用未触=0 误杀后者。INTERIM 可 CLOSED；产物失败仍出保底报告，无人签署不阻止报告。模板内嵌本闸及锚。报告第一节逐 persona 写「业务目标｜实际连续路径｜完成/失败/受阻｜入口可见结果｜主证」，不新增旅程通过率 KPI；需求/证据/未触指标退居审计节。TECH-OBS 无 persona 入口失败关联时不得形成 UAT ❌。

**【定义权归属】**报告三态、产物树核心约束、缺陷与证据命名归 SUA；ACG 只在生成期读取并内联冻结快照。产物优先级=SUA 核心约束>任务书合法 profile/扩展>默认布局。出处为静态元数据，不是运行时读取指令；外部后续变更不追溯修改已签发报告。

## 治理模式（辅）

对既有常驻验收契约（详见 `references/pollution-taxonomy.md`）：
1. **体检**：按 `references/executable-standards.md` 的完整 29119-3/29148 对照矩阵核查（涵盖设计/用例/规程/计划/完成报告，不仅看 AC-ID）；逐项列证据与影响并分级：P1=Shall 级违规/阻塞，P2=必需信息缺失，P3=改进建议。打分不能代替逐项缺陷与证据。
2. **历史污染治理**：内嵌状态快照→台账指针；内联版本标签→清除；执行表历史注记→清除（保留 ⛔/⏭️/⏸️ 执行门槛）；历史唯一合法位置=Changelog。
3. **三件套拆分**：自检脚本/命令手册/端点基线/账号下沉执行层（`<项目>/tests/playbooks|fixtures/`），契约原位留指针。
4. **迁移/新建**：新项目按模板生成四件套空骨架（占位符）——骨架见 `templates/project-skeleton.md`（主契约/执行手册/基线夹具/机读台账四层+层间指针纪律）。

**角色边界**：项目规范正典（如 `<项目>/docs/` 下的验收指令）默认只读——产出=草案/递单，转正走维护人；任务内明确授权除外（在报告注明授权出处）。若另有进度监控/任务管理层，它只负责进度与状态，不代替质量自检或擅自改判；安全授权和判据冲突只暂停受影响作用域，独立 READY 项继续，报告签发不等待裁定。

- [ ] **页面内容全覆盖机验**：生成期对每管理页输出「页面内容清单」——页上全部交互控件（按钮/筛选器/下拉/翻页/链接/开关）与数据呈现区（表列/字段/卡片/文案区）逐项列明；逐项落 ≥1 验收点或显式 N/A+理由（机验：清单行数=落点行数+N/A 行数，双向差集=返工）。执行期以 G0/巡检核对渲染与清单一致（缺项=清单漏列或产品变更→记偏离）——覆盖粒度从「每页 ≥1 点」提到「页上每个元素有落点」

- [ ] **判据条款级追溯**：§3 每个 AC 的「预期」可逐条回溯到 test basis 条款（PRD/设计/接口规范章节号或条款锚，产品裁定附日期）；无条款可溯的预期标 ⏸️ 或显式「合理期待/行业惯例」（口径见 references/provenance-gate.md「判据条款级追溯」）
- [ ] **实现差异扫描已留痕**：交付含「规格↔实现」双向差集表（规格有实现无→⏸️/实测记录；实现有规格无→补点或 N/A+理由）（口径见 references/source-reconciliation.md「实现差异扫描」）
- [ ] **负向基线核查（P1）**：每个负向用例逐条挂正向基线；无正向基线的点记 ⏭️+通道三选一结论，不得计入负向占比（负向/(正+负) 计算前剔除无基线项）
**G5 计数与收官**
- [ ] 计数机跑一致：**唯一合法口径 = references/self-check-gates.md §1 scan 函数**（§3 区间扫描+门槛前缀行收集，两个方向的真书误判实证见 §1）；scan 出的唯一 AC-ID 数必须等于文档头部/范围段/§3 标题/覆盖表分母/完成准则/汇报模板的每一个数字；旧版段头数字必须重跑不复用
- [ ] **收官与保底闸内嵌**：先过 UAT 身份/真实旅程闸，DOC-only 只能 coverage-audit；再按 INTERIM→WITH-GAPS→FINAL 校验；任一 PARTIAL 必 INTERIM，合法 ⏸️/外部/S/G 可 WITH-GAPS，FINAL 需 S+G=0、O=P；格式失败不阻止保底报告
- [ ] **所选规范冻结快照（P1）**：拟人旅程、授权、收官、产物、用户报告、缺陷和所选模式条款完整内联，附静态出处+哈希；SINGLE_WRITER 必带自主长任务内核，不多带并行接管 schema；无动态当前版本指针或外部执行依赖

**G6 任意 Agent 可执行**
- [ ] 任意 Agent 可执行：文档内嵌执行者手册（角色代入/工具要求/执行规程/判定纪律/降级路径），不依赖执行方拥有特定技能
- [ ] 执行工具平台无关：不要求 OpenCode、特定浏览器驱动、固定凭据变量名或某个专用执行技能；工具要求写成可替代能力，缺工具时提供安全降级路径
- [ ] 拟人纪律内嵌：真实 persona 从动机到最终结果连续走真实入口；人类 GUI/TUI/CLI/API 均属 UI，但 GUI 主界面可达时必须真实 GUI 事件，MACHINE 只给真机器调用方；源码/DB/日志仅辅证；多账户隔离；清场仅限本轮精确对象
- [ ] 多角色账户覆盖：按场景列出账户别名—角色/权限—用途映射；涉及多角色时分别用对应权限账户执行正反向旅程，验证跨角色边界；不得要求整轮只用一个账户，也不得用高权限账户代替低权限角色；仅单角色系统可声明单账户并给依据
