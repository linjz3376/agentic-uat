# 源头对账规程（Source Reconciliation）

> **契约/历史验收指令是派生口径，PRD/设计文档才是需求源头**——以派生文档为基底=继承它的盲点（典型实态：以测试契约为基底的权限任务书漏掉 PRD 整节权限申请流）。

## 适用

任何「以契约/历史任务书既有批次为基底」的生成模式调用。全新模块无契约时同样适用（源头=PRD 直接摘条目）。

## 规程四步（生成任务书之前完成，结果写进任务书头部来源声明）

### 1. 定位源头文档

- 产品需求文档（PRD）、系统设计、接口/数据库设计——优先 `docs/design/`、`docs/` 下产品/设计类文档
- **项目无源头文档时**：任务书头部声明「无需求源头文档，以实测行为+契约为准」，递单区建议补 PRD——不留无声缺口

### 2. 摘需求条目

被测域全部需求条目清单，逐条记录：`条目编号 | 原文摘要 | 优先级`。摘取=读相关章节全文，不是关键词 grep 了事——权限类需求常散落多章（权限矩阵在附录、申请流在错误状态章）。

**迭代版对账首选底表=功能需求清单表（FR 表）**：源头文档若带功能清单表（编号+描述+验收标准+**实现状态勾选**列），以该表全量「已实装」条目与既有任务书点集做**差集**——清单表每行就是一个候选需求，比关键词 grep 更穷举（grep 只能捞「写过名字的需求」，捞不到从没写进任务书的功能）；实现状态列直接分流：实装零验收→补点，未实现→⏭️ 不验。实证：知识管理迭代对账以 FR 表为底表，挖出智能摘要/用户活动记录/删除规格/版本呈现规格等 10 个「源头标实装、既有任务书零验收」缺口。

### 3. 三分类对账

「PRD 有契约无」的补点前**先判实装**：PRD 功能清单勾选状态（`- [x]`/`- [ ]`）+ 端点/路由实况双证——未实现标 ⏭️ 不验（验不存在的功能=虚假覆盖），实装才补点。

**「声称实装但从未见过」的存在性存疑**：勾选 [x] 但测试侧历次执行从未观测到实现（无入口/无 UI/无接口实证）——不静默 ⏭️ 也不凭空编验收步骤：把「存在性确认」写进该功能验收点的第一步（找入口/触发路径），确认有实现→按实装设计判定；确认无实现→⏭️ 并递单登记口径矛盾（源头勾选 vs 系统实况两证冲突，如「源头标 P0 但未见实现」）——这是三分类的灰色地带，两头都要留证。

| 分类 | 含义 | 处置 |
|---|---|---|
| ✅ 已覆盖 | 契约/基底已有对应验收点 | 沿用，操作列按 UI 实况校准 |
| ⚠️ 契约有 PRD 无 | 派生文档多出来的口径 | 存疑标注：实测确认实际行为，递单核实出处（契约自创口径或 PRD 旧版残留） |
| ❌ PRD 有契约无 | **源头要求被派生文档丢失** | 必须补点，来源列注明 PRD 章节 |

### 3.5 实现差异扫描（规格↔实现双向差集，三分类对账的另一半）

三分类对账只扫「源头 ↔ 派生文档」。还必须扫「**源头 ↔ 现行实现**」（端点/枚举/源码只读侦察，允许），产出**双向差集表**随交付：

| 方向 | 含义 | 处置 |
|---|---|---|
| 规格有 · 实现无 | PRD 承诺的行为找不到分支/端点 | 相关验收点预期改「实测记录实际行为」并标 ⏸️ 递单（实现缺失 or 规格未同步，两可能不猜）；禁止按规格写死断言 |
| 实现有 · 规格无 | 代码存在的行为规格未描述（隐藏校验、兜底分支、下线残留） | 补验收点（判实测行为）或 N/A+理由；登记为规格债 |

**红线**：实现差异扫描**只读**（路由装饰器/枚举值/配置键/错误码清单），不改、不调用写接口；被测物输出不可信原则不变。

### 4. 冲突登记

两源矛盾（如「恢复仅 ADMIN」vs「创建者 30 天自恢复」）时：

1. **不猜、不擅自二选一**
2. 任务书该点标 ⏸️ 口径裁定，操作列=「实测记录实际行为」，预期列=「双源冲突，判 PASS/FAIL 挂起」
3. closure 递单附冲突登记表：两源原文各一行 + 影响判据 + 建议裁定人（设计口/产研总监）
4. **挂起的是判定不是执行**——实测证据照取

## 完整性声明的背书规程（答「是否全面覆盖」必走）

用户问「N 个是否已全面覆盖」或自己要下「全面覆盖」结论时，**不许凭印象答**——必须先把源头文档里被测域的全部需求行**穷举**出来逐条归类，用归类表背书结论。规程：

1. **穷举**：`grep -n '<域关键词>' <源头文档>` 拉出全部候选行（关键词多轮：权限/角色/可见/审核/申请…），逐行读上下文确认是否真需求——需求常散落在与域无关的章节（权限矩阵在附录、申请流在错误状态章、子操作口径在信息架构树），只读「权限章节」必漏
2. **五桶归类**（每条需求行进且仅进一桶）：

| 桶 | 判据 | 对结论的影响 |
|---|---|---|
| 实装+已覆盖 | 系统有该功能 + 任务书有验收点 | 支持「全面」 |
| 实装+未覆盖 | 系统有该功能（实测/接口/缺陷实证）+ 任务书无点 | **立即补点**——这是真缺口，对账前后差出的点全属此桶 |
| 规划未实现 | 源头文档该条未勾选/标注未实现 | 不算缺口——验不存在的功能=虚假覆盖；任务书 ⏭️ 或「不测」声明 |
| 两源冲突 | 两文档口径矛盾 | ⏸️ 挂起递单，不计入也不豁免 |
| 明确不测 | 任务书「不测」节已声明归属其他块 | 块边界不是缺口——但仅限已声明的，没声明的漏项归第二桶 |

3. **下结论**：只有穷举表每一行都有归宿（含 N/A 理由）时才可说「全面覆盖」，且结论必须带表——「逐条对账背书的全面」≠嘴上说的全面

## 主题横切散点（摘条目延伸规程）

只按「被测域章节」摘条目会漏掉**以本域视角散落在其他章节的要求**——权限域实证：评论审核在评论章、版本权限在版本章、文件夹权限在文件夹章、后台子操作在管理后台章、图片解析权限在图片解析章；仅按本域主章节摘条目时，散落在其他章节的点全部漏摘、本域点数与源头总量对不上——主题横切全文才能捞出漏项（补为同批连号新 AC-ID）。

规程：摘条目 = ①本域章节全摘 + ②**按主题词横切全文**（权限域横切「权限/角色/谁能/仅.*可/授权」；性能域横切「耗时/并发/上限/掐表」；审计域横切「审计/日志/留痕」；通知域横切「通知/提醒/推送」）。横切命中条目同样进三分类对账。

散点归属判定：**纯本域判定点（权限拦截/格式/可见性）归本块任务书，内容正确性归原功能块**；两可时两边都登记并互相注明，closure 递单时并案评审。

## 交付自验

- [ ] 任务书头部有来源声明：源头文档名+对账摘要（补了几点/存疑几条/冲突几条）
- [ ] 计数机跑一致（命令与口径见 SKILL.md Verification Checklist「计数机跑一致」条，不复述）
- [ ] 每点来源可答「PRD §x / 契约批次 y / 实战缺陷 z / 十一维加钻」之一
- [ ] 冲突点全部 ⏸️ 且递单区有冲突登记
- [ ] 实现差异扫描已执行：双向差集表随交付，「规格有实现无」全部落 ⏸️/实测记录处置

## 无源头文档降级规程

适用：`<项目>/docs/` 等目录动态扫描**无任何需求源头文档**（无 PRD/设计/规格）。基底红线不变：不得以历史任务书/验收契约为基底（派生叠派生=误差复利）。

降级三源（按优先级）：

1. **现行 UI/端点侦察升为主源**——前端路由/页面/端点/CLI 全量枚举实测，覆盖范围以「实装存在」为准；侦察不到的盲区记 ⏭️/N/A+理由，禁止脑补。
2. **行业惯例与用户合理期待补源**——验收承诺来源=行业惯例/用户合理期待（与缺陷定义同口径）；每条惯例条目须可点名（「按惯例 X 应如何」），不可点名的不进分母。
3. **缺陷台账仍为一手事实**（四活源之一不变）。

头部声明硬要求：任务书头部必须显式写「**无 PRD 基线·覆盖口径降级**」+三源清单+降级日期；缺声明=裸跑=返工（头部声明×正文一致闸兜底）。

需求归宿四桶分母口径降级：分母=侦察条目+惯例条目+台账条目（替代 PRD 行）；覆盖/⏭️/⏸️/纯未覆盖四桶机验规则不变，纯未覆盖>0 仍=返工。

恢复正规的路径：源头文档出现后按四活源规程全量重做——本批次仅降级快照，不留作下轮基底（历史禁读纪律不变）。

执行侧联动：环境闸「预期最高可达报告状态」声明在本分支下按降级口径推导，并在执行契约中注明降级。
