# AC-ID 规则与 golden set 结构

## AC-ID 格式

`AC-<域>-<点号>[<子字母>]`
- 域：批次号（01 至 99，可带子批 A/B/C，如 07A/12C）或功能域缩写（新功能开新域，如 IM/RPA）
- 点号：三位流水（001 至 999）；子字母（A/B/C…）用于同点插项
- 例：`AC-02-002A`=批次2点2的插项 a；`AC-IM-003`=IM 功能域第 3 点

## 铁律
1. **ID 终身不变**：验收点插入时用下一个空号；禁止重排（对账/报告引用全靠它）
2. 废弃点行保留，显式标记「已废弃：AC-xx-xxx」并注明原因与日期，**号不复用**；不得用删除线表达状态
3. 新功能域开域规则：主契约无对应批次 → 开 `AC-<域>-###`；后续若并入主契约，旧 ID 保留映射（一行指针）
4. 追溯矩阵随 ID 同步更新，字段：`AC-ID | 域/批次 | 需求来源（PRD 章节等） | 页面/对象 | 门槛 | 关联缺陷编号`
5. Cell/Case/Run 使用各自独立 ID：AC 子字母只用于同点插项，不用于数据组合、执行子用例或复验；复验复用 Case 并新建 Run，场景重排不改 AC/Cell/Case

## golden set（AI/LLM 类验收判据）

### 为什么需要
「回答合理/语义相关」不可机判（29148 可验证性违规）。golden set = 标准问答参考集，命中问题必须满足全部断言，未覆盖问题显式转人工判定——杜绝主观判。

### 文件结构（`<项目>/tests/fixtures/ai-golden-set.json`）

```json
{
  "version": "<semver>",
  "owner": {"structure": "质量", "content": "业务/产研（回答正确性是业务口径）"},
  "usage": "<哪些 AC-ID 以此为判据>",
  "rules": [
    "每条 case 至少 1 个 mustCite（期望引用条目）或显式 []（免引用）",
    "assertions 用可机判谓词（含字段/计数/时序），禁主观词",
    "priority: P0=验收必过; P1=FAIL 须报 Bug",
    "每次验收把『判得准的问题』回填为新 case",
    "case 内容变更需业务确认"
  ],
  "cases": [{
    "id": "GS-<域>-<###>",
    "priority": "P0",
    "question": "<标准问题>",
    "mustCite": [{"titleContains": "<期望引用条目标题特征>"}],
    "assertions": ["<可机判谓词>"],
    "forbidden": ["LLM_ERROR", "<禁止出现的模式>"]
  }]
}
```

### 使用规则
1. 验收点文档的判据表加一行：AI 类问题 golden set 命中→必须满足全部断言；未覆盖→记录实际输出+引用源，转人工判定
2. 种子条目由生成模式带入 fixture；内容归业务/产研回填
3. golden set 是项目事实资产，随执行持续扩充（每次验收沉淀判得准的问题）
