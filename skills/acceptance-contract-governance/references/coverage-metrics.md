# 覆盖度量口径（唯一权威）

> 本文件是覆盖公式**唯一权威源**：ACG 生成时读取并把公式内联进任务书冻结快照；SUA 自检 #15–16 使用内联公式，不另定义分子分母。技能不依赖 Python/Node/Shell；机算优先，工具缺失时手工对账并留痕，不得虚构结果。

## 1. 三个度量（执行期，报告头机算）

| 度量 | 公式 | 分子细则 | 分母细则 |
|---|---|---|---|
| 需求覆盖率 | 本轮实际发生产品验证的需求源条目数 / 需求源条目总数 | 对账表「执行期落判」证明至少一个承接 AC 实际为 ✅/❌/PARTIAL/⏸️；只有设计期「覆盖」桶或全部 AC 仍 BLOCKED 不得计入。⏸️ 有实测观察可计入，⏭️ 不计 | 覆盖对账表逐条登记的需求源条目总数 |
| UI 证据覆盖率 | 有判定时截图/DOM 的 UI PASS 数 / UI PASS 数 | 判定时的截图或 `[DOM]`；事后补证不计 | 全部 UI PASS 数；0 时 N/A+理由；大于 0 且低于 100%→INTERIM |
| 未触率 | 归因审计后仍为 BLOCKED 的唯一 AC 数 / AC 总数 | 六类 BLOCKED 全部计入，包括转 UNREACHABLE 后仍 BLOCKED 的项；只有补测后已不再 BLOCKED 才剔除 | §3 主表全集唯一数（scan 口径） |

**⏭️ 不计入需求覆盖率分子**。⏭️ 是「有证据的未实现/不适用」声明：它闭合该点（收官闸意义的终态归宿），但产品侧验证未发生，不构成覆盖率意义的落判。此细则把执行侧「有终态落判」操作化为「有产品验证落判」——两词之差即 38/45 与 45/45 之差。

实证（某全域轮任务书）：45 条需求 = 覆盖 34 + ⏭️ 7 + ⏸️ 4 + 纯未覆盖 0 → 需求覆盖率 = (34+4)/45 = 84.4%；另 7 条 ⏭️ 为产品未实现，不压测试责任、也不垫覆盖率。

分母为 0 → 写 N/A+理由；机算优先，工具缺失手工对账留痕。

执行期对账表固定列：`需求条目 | 条款出处 | 承接 AC | 设计期桶位 | 执行期落判 | 是否计入分子`。执行期落判必须来自本轮实际 AC 状态，不得直接复制设计期桶位。

## 2. 设计期度量（生成期，任务书头部/回执）

| 度量 | 内容 | 闸 |
|---|---|---|
| 需求归宿分布（四桶） | 覆盖 / ⏭️ / ⏸️ / 纯未覆盖 各机验数 | 四桶计数与头部声明逐桶一致；**纯未覆盖必须为 0**（ac G4 P1）；回执七项摘要必报 |

四桶定义（设计期口径）：

- **覆盖**：≥1 个验收点承接该需求条目；
- **⏭️**：产品未实现/不适用，标 ⏭️ **且带声称出处 + 侦察证据**（缺任一 → 桶位无效，视同纯未覆盖）；
- **⏸️**：源间口径冲突，挂 ⏸️ **且进冲突登记表**（§8 或等价节，缺登记 → 桶位无效）；
- **纯未覆盖**：无任何承接且无上述任一理由——**出现即返工**。

## 3. 机验算法

### 3.1 归宿四桶计数

1. 定位覆盖对账表，先按表头取得「设计期桶位」列号，逐需求行读取**该列**，禁止按尾格位置猜。
2. 桶位列归一化：去注释与空白→覆盖/⏭️/⏸️；无 AC 且无合法桶位=纯未覆盖。
3. 执行期另读「执行期落判」「是否计入分子」列；尾格仅是分子判定，不得当设计期桶位。
4. 判定：四桶计数==头部声明，且总数==需求行数。六列正例 `需求/出处/AC/设计期桶位/执行期落判/是否计入` 必须可读。

### 3.2 §3.5 深度表并集闭合（含同域缩写展开）

1. 主表全集 = self-check-gates §1 scan 口径（区间扫描 + 门槛前缀行收集）；
2. §3.5 各行按 `AC-<域>-<基号><接续令牌>*` 抽取，接续令牌两种：
   - `~NNN` 区间 → 展开为 基号..NNN **全号段**（`AC-IMP-201~218` = 201..218 逐号展开）；
   - `/NNN` 列举 → 追加该号（`AC-IMP-202/210/215` = {202, 210, 215}）；
3. 取并集 U_D，**双向**对账：
   - 主表有而 U_D 无 = **漏标维度** → 返工；
   - U_D 有而主表无 = **幽灵标注** → 返工。

**陷阱实证（某全域轮任务书审计）**：裸正则只抓首号，会把 `201~218` 误读为单点 201、把 `203/204` 误读为 203——曾致并集 94/128、假差集 34 项；按上法展开后为 127/128，唯一真差集 = 1 个漏标维度的 AC（书写缺口，1 点）。**本闸禁止裸正则上岗**（凡含正则的闸先一正一负活体测，见 SKILL.md Verification Checklist 总则）。

## 4. 反 gaming 与禁用口径

- **产品质量不设及格线**：需求覆盖率只报数，不设「≥X% 产品通过」线——产品未实现会压低需求覆盖率，设线只会逼虚标 ⏭️/乱挂 ⏸️。**唯一例外是证据完整性**：UI PASS 必须有判定时 UI 主证，这是报告可信度合规闸，不是产品质量分数，也不要求功能全 PASS；
- ⏭️ 虚标拦截 = §2 出处+证据双要件；⏸️ 虚标拦截 = §2 登记表要件；桶位无效视同纯未覆盖（返工）；
- 禁止以历史任务书的需求条数为分母（派生口径不作 basis）；禁止跨轮拼接覆盖率；禁止把 ⏭️ 计入需求覆盖率分子（§1）。

## 5. 设计期 vs 执行期分工总表

| 层 | 度量/闸 | 归属 |
|---|---|---|
| 设计期 | 归宿四桶（纯未覆盖=0、桶位要件） | ACG G4 P1，属于设计完整性闸 |
| 执行期 | FINAL/FINAL-WITH-GAPS/INTERIM | SUA §6 唯一判定；FINAL 才要求 BLOCKED=0 |
| 执行期 | UI PASS 主证 100%，不足则 INTERIM | SUA §5 #12–14，属于证据完整性闸 |
| 执行期 | 三度量按公式报数 | SUA §5 #15–16；需求覆盖率不设产品质量线，工具缺失可手工对账留痕 |
