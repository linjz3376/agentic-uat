# 深度设计维度（生成模式·重点测必走）

> 触发条件：用户说「重点测」「深度测」「安排测试任务」时**强制走本清单**。
> 从主契约平移既有验收点只解决广度；深度 = D1 功能正确性（内容判定与对比）+ D2 至 D11 失效模式排查。
> 每个维度必须产出 ≥1 个验收点，或显式记 **N/A + 理由**（不许静默跳过——静默跳过是深度造假）。

## 为什么需要它

「重点测某功能」与「跑一遍主契约对应批次」是两件事。主契约服务全域均匀覆盖；重点测要求对该域做两件事：
1. **功能正确性**——这个模块的产出物（内容/数据/计算结果）对不对、全不全、各处显示一不一致（内容判定与逐字段对比）；
2. **失效模式排查**——边界/权限/并发/异常注入等十一维系统排查。

只搬主契约点 = 广度平移（点数字面上百，深度与主契约无异）；只堆机制维度 = 舍本逐末（安全边界全绿，正文内容显示错字漏段没人发现）。**D1 永远先行，但占比按域类型分档；防线型域不要求 D1 高于 D3/D9**。

## 十一维检查表

| 维度 | 核心问题 | 典型验收点形态 | N/A 理由形态 |
|---|---|---|---|
| **D1 功能正确性·内容对比**（首维，功能测试核心） | 产出物内容对不对？输入↔回显↔DB↔多端渲染**逐字段/逐元素**对比做了吗？文件解析内容保真吗（不只是 MD5——解析出的标题/段落/表格/图片数对不对）？**元素相对位置/顺序与源文档结构树一致吗（版式保真）？解析出的图片/图表真能渲染、还是占位/裂图？** **AI 回填内容（智能图片描述/表格摘要/自动标签）与源真值对账了吗——不是「存在即对」，是内容描述 vs 源像素/源数据的误差定性？** 文档类型/格式等元数据在列表、详情、编辑、搜索各端一致吗？**产品声称支持的每种输入格式/类型（前端 accept/白名单/PRD 能力清单）各有保真验收点或显式 N/A 吗——只测默认格式=漏整个格式矩阵**？**导出/报表/下载类数据出口的内容与页面/DB 对账了吗**（导出 CSV 逐格、报表数值逐格——按钮存在≠内容正确；实证：权限任务书漏导出验证）？版本 diff、搜索命中片段、推荐相关性，都有可机判对比规则吗？ | 实体×页面×字段核对矩阵（差异=❌）；上传文档解析产物 vs 原文**结构树逐节点对比（顺序+层级+位置）**；图片/图表逐张渲染核验（非裂图、非占位）；**AI 回填文本 vs 源真值对账表（夹具真值可造：纯色图/已知数据表 → 描述误差定性）**；类型/来源字段多端一致性矩阵；版本回滚后内容逐字对比；搜索片段⊆原文子串断言 | 「纯配置无内容实体」（罕见，理由需充分） |
| D2 等价类/边界值 | 每个输入域是否派生边界候选并按风险档选择？关键档临界±1与高风险值全做，标准档代表抽样，共享字段去重 | 长度下限-1/下限/上限/上限+1；空/NULL；非法格式；候选与计划分母分列 | 「本域无用户输入」 |
| D3 权限矩阵 | **角色×操作全矩阵**建了吗？每个 🚫 格子都有负向用例吗？是否使用各角色对应的不同测试账户走自己的旅程，防止管理员账户掩盖普通用户越权/不可达问题？ | 矩阵表（角色列×操作行，✅/❌/🚫），每 🚫 一格=1 负向点；使用对应角色账户分别验证允许/拒绝路径；未登录 401 | 「单角色系统」（需由需求/实装确认，并在任务书声明依据） |
| D4 并发/时序 | 两个用户/两个动作同时发生会怎样？双击/重试幂等吗？ | 双人同编同一记录；删除瞬间被评论；双击提交计数=1；并发点赞计数正确 | 「纯静态只读域」 |
| D5 状态机/生命周期 | 实体状态迁移全验了吗？定时任务（到期/自动清理）验了吗？ | 软删→到期→自动清理 job 执行；版本 ≥3 + 回滚；状态反转（收藏↔取消） | 「无状态实体」；**业务不允许/事件驱动**（迁移按 PRD 口径不支持主动构造、或属真实业务时点事件）——记 N/A+PRD 行号依据，不归因代码缺陷 |
| D6 失败注入/异常路径 | 中途失败留下什么？后端 500 前端怎样？依赖挂了降不降级？ | 上传中断→无孤儿文件；DB 失败回滚；停 ES/Redis 后列表表现（记录实际降级行为） | 「无外部依赖调用」 |
| D7 一致性量化 | 「最终一致」的**时延上限**量化了吗？ | 索引同步 ≤N 秒；缓存 TTL 上限；分页中并发新增的总数漂移 | 「无异步/缓存链路」 |
| D8 性能基线 | 首屏/提交/上传耗时阈值定了吗？ | 列表首屏 ≤3s；提交响应 ≤2s；进度条真实更新 | 「后台批处理无 UI」 |
| D9 安全 | XSS（存储型优先）/注入/越权 IDOR/恶意文件/不安全跳转，每类至少 1 点？ | `<script>` 入标题/评论渲染转义；URL 直改他人资源 UUID；伪装扩展名上传 | 「纯内网无外部输入」（罕见） |
| D10 可观测性 | 用户/调用方能否诊断结果？内部审计字段仅作 TECH-OBS；审批/申请通知必须从申请人或真实机器调用方入口验送达 | 入口可见状态/通知为主证；audit_log 字段完整仅作技术观察，无用户影响不直判 UAT ❌ | 「无敏感操作」 |
| D11 体验/兼容 | 回退/前进、半填表单、多标签页同步、空态文案，验了吗？浏览器兼容/分辨率/多语言/可访问性想到了吗——企业内部单语言桌面 Web 可显式 N/A（理由写「企业内网桌面 Web 单语言」），**但不许没想到**？ | 回退后列表页码保持；半填刷新保留；A 页删除 B 页同步 | 「无交互页面」 |

## 密度与配比基线（P2 偏离标注，不是产品全绿门槛）

1. **D1 占比按域类型分档**（一刀切 40% 对防线域常态化偏离=基线形同虚设，故分档）——内容型域（知识/文档/数据类，D1 本体）≥40%；防线型域（权限/安全/审计类，D3/D9 本体）D1 ≥15% 且 D3+D9 合计 ≥50%；流程型域（审批/工作流/配置流类，D5 本体）D1 ≥25% 且 D5 ≥20%。分档后仍低于基线才走「如实标注偏离」出口
2. **负向用例占比基线 ≥30%**（异常输入+权限负向+失败注入+安全负向 ÷ 总点数）——低于基线必须写风险与偏离原因；关键安全/权限负向不得抽样降格
3. **D3 权限矩阵无空洞**：每个 🚫 格子必须有对应验收点
4. **点数不设下限指标**——维度完备性（十一维全有点或 N/A 理由）替代点数考核，防凑数注水
5. **窄域小任务**：总点数 ≤8 时不强制百分比，也不设绝对点数下限；所有适用的高风险、D1、负向和 D3 拒绝格必须有着落，不适用项给可核 N/A。不得为凑数新增重复点，豁免在七项数字摘要中标注

## 深度证明表（随任务书交付）

任务书增列「深度维度覆盖表」：十一维 ×（对应本表 AC-ID 列表，或 N/A + 理由）。执行者与评审据此一眼看出深度是设计出来的还是碰运气碰出来的。

多条件业务域另按 `coverage-metrics.md §3.3` 建 Cell/Case profile：D1 至 D11 是测试技术轴，Cell 是业务条件轴，两者正交。不得用十一维全勾替代具体条件格，也不得用 Cell/Case 数量替代 D1 内容保真、D3 权限拒绝格或其他高风险深度。

## 常见造假形态（自查红线）

- 把主契约的点换个说法重新计数（平移 ≠ 深度）
- 维度表写「全覆盖」但验收点表对不上号
- N/A 理由写「显而易见」「不重要」——这不是理由
- 边界值只测超界不测临界（200+ 测了、199/200 不验）
- D1 用「内容显示正确」一句带过——没有逐字段/逐元素对比规则 = 没做 D1
- 解析保真只数数量（标题数/表格数/图片数全勾）就放行——**不核元素顺序与源结构树、不核图片真能渲染、不核 AI 回填内容 vs 源真值** = 数量保真冒充内容保真（实证：三级标题/2 表/2 图数量全对，但位置、回填真值、裂图风险均未核）
- **格式矩阵漏对账**：前端 accept/后端白名单/PRD 能力清单列出的支持项（格式/图片类型/协议）是现成的等价类全集——逐项要么有保真验收点要么显式 N/A；只测默认格式（如 docx）就声称覆盖上传=漏整个矩阵（典型实态：accept 列十格式、图片四类型，任务书只测了 docx）
- **看板/列表「恒 0」当无数据放行**：页面无数据可能是假数据或未加载——先以模拟用户方式观察操作前后可见结果是否变化；仍有疑问时可由生成者/诊断者检查实现或数据源作为**辅证**，但源码/API/DB 检查不属于模拟用户执行步骤，也不能替代用户侧验收。mock 冒充真实数据属于风险；在用户界面无法证实时如实标记部分/挂起，不因内部数据存在而判 UI 通过。
