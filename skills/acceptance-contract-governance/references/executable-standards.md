# 可执行性标准与 29119 对照

## 六条主标准 + 补充标准 7/8/9（交付前逐条自验）

| # | 标准 | 判据 | 常见违反 |
|---|---|---|---|
| 1 | 稳定 AC-ID | 每验收点有 ID，全局唯一，规则见 ac-id-rules.md | 用行号/批次号当 ID（插入即漂移） |
| 2 | 操作可直接执行 | 命令/路径真实存在且探过可达；产品 AC 首令牌为 `[UI]`/`[MACHINE]`；纯对账用独立 AUDIT-ID，不占 AC；无「点击某处」式歧义（除非附定位方式：路由/选择器） | 凭记忆写路由（应先生成路由地图/harness 再写）；漏标入口类型 |
| 3 | 预期可机判 | 量化阈值（进判据表）或显式标注「人工判定」；`[MACHINE]` 点须可断言状态码/业务错误码/鉴权/关键字段；有状态变更时才另核幂等和副作用 | 「显示正常/语义相关/体验良好」裸奔；只写「返回 200 即通过」 |
| 4 | 环境前置成段 | GO/PARTIAL/NO-GO 可判定：可达/健康/账号/依赖逐项 | 前置散在正文，执行时才现凑 |
| 5 | ⛔ 门槛链接台账 | 只写台账条目编号，状态以台账为准 | 复制缺陷状态进文档（双份漂移源） |
| 6 | 完成准则 checklist 式 | CLOSED=AC 均有合法终态/归因+判定登记+报告签发；❌/⏸️ 可结束本轮，缺陷修复与风险接受另行跟踪 | 把全 PASS 或缺陷全修当成停止/出报告前置 |

### 补充标准 7/8/9（场景与 UI 主证 + 执行契约骨架）

| # | 标准 | 判据 | 常见违反 |
|---|---|---|---|
| 7 | 真实旅程完整 | 至少一条真实 persona 产品旅程；动机/起点/连续基本流/交接/最终结果齐；AC 挂靠与场景完成分开；禁止域批吞并全部 AC；异常恢复成对 | 只闭合矩阵；G-DOM 关联全部 AC；只有控件清单没有业务目标 |
| 8 | 人类界面主证 | GUI 有截图/DOM，TUI/CLI 有终端读屏/输出，人类 API 有调用方可见响应+最终业务结果；对话框双路径；MACHINE 有真机器契约；DOC 独立审计 | 用内部 API 判人类界面；只验确认；DOC 冒充产品验证；事后补证 |
| 9 | 所选执行模式冻结 | SINGLE_WRITER 默认含共享状态机/逻辑四态/长窗收判/超时/最小断点；PARALLEL_UNATTENDED 仅实际并行/接管时内联租约/CAS/fencing/分片归并；静态出处不作运行依赖 | SINGLE_WRITER 携带 CAS/fencing；PARALLEL_UNATTENDED 缺恢复；动态追随外部版本 |

## ISO/IEC/IEEE 29119-3 对照（治理模式体检用）

| 物项 | 级别 | 要求 |
|---|---|---|
| Test Design Spec | Shall | feature set：唯一 ID/目标/**优先级**/策略摘录/**追溯** |
| Test Case Spec | Shall | 唯一 ID/目标/优先级/追溯/**前置条件/输入/预期结果**/实际结果与结论 |
| Test Procedure Spec | Shall | test set：唯一 ID/目标/组成用例；与 Test Design 分离存放 |
| Test Plan | Shall | 测试项/范围/风险登记/策略/完成准则/度量/环境/数据要求/暂停恢复准则/人员角色/日程 |
| Test Completion Report | Shall | 执行摘要/偏离/完成评价/度量/残余风险/交付物/经验教训 |

体检输出分级：P1=Shall 级违规（阻塞）/ P2=缺失项 / P3=建议。

## ISO/IEC/IEEE 29148 可验证性判据

「好需求/好判据」特征：必要 · 恰当 · **无歧义** · 完整 · **可验证** · 正确 · 一致 · 可追踪。
可验证=存在某种方法能以有限成本判定满足与否。模糊词量化法：

| 模糊词形态 | 量化路径 |
|---|---|
| 「明确/清晰」 | 含错误类型+原因+建议任一要素，且不含技术栈细节（抓组件文案关键字匹配） |
| 「快/流畅」 | 时间阈值（分场景：静态<1s/CRUD<2s/复杂查询<5s…） |
| 「正确/一致」 | DB 直查对账公式（COUNT/字段比对/ORDER 验证） |
| 「同步/生效」 | 反向操作+F5 验证 + TTL/缓存过期上限 |
| 「合理/相关」（AI 类） | golden set 条目断言（结构见 ac-id-rules.md）；无条目=显式人工判定 |

## 形态原则（再强调）

复用次数决定形态：
- **常驻主契约**（服务多轮）→ 设计/规程/数据三层分离；历史唯一合法位置=Changelog；状态快照=台账指针
- **一次性任务书**（服务一轮）→ 自包含单文档；可复用产物执行后回写 fixtures
