# 历史污染诊断与治理（治理模式）

> 适用对象：常驻验收契约/测试文档。一次性任务书不需要本清单（生命周期=一轮）。

## 三类历史污染（诊断→处置）

### 第一类：内嵌状态快照
- **形态**：文档内嵌「已知 Bug 状态摘要」「当前进度」「X 已修/Y 未修」表
- **为什么有害**：状态是流动值，文档版本是静态的——快照自写入起即漂移，双份事实源
- **处置**：改「快查+指针」结构——一节只放：①单一事实源路径（缺陷台账，机读+人工镜像）②最后核对日期 ③当前阻断项编号列表（不复制状态）；执行者以台账为准

### 第二类：内联版本标签
- **形态**：正文/表内「(V2.x 新增)」「(V2.x 修订)」「commit <短哈希>」「2026-09 实装」
- **为什么有害**：读者被迫考古；版本化注释随时间堆积成噪声层
- **处置**：正文一律清除版本归因；历史唯一合法位置=文末 Changelog（标注「不参与执行」）；技术实质保留（如「认证方式：HttpOnly Cookie」），仅删时间/版本/commit 装饰

### 第三类：执行表历史注记
- **形态**：批次表/用例表尾列写「已修订」「已转正」「新能力」「已实装」「回归 #XX」「FR-<编号> 闭环」
- **为什么有害**：执行者关心的是「现在该验什么、什么算过」——历史注记稀释门槛信号
- **处置**：尾列只保留**执行门槛**——⛔ 阻断（链接台账编号）/ ⏭️ 探索无实现 / ⏸️ 待重验；其余清空。表头加「修订标记」列说明：本列仅执行门槛

## 三层分工（治理后应呈现的结构）

| 层 | 载体 | 内容 |
|---|---|---|
| 执行契约 | 本文档 | 当前有效的验收点/预期/阈值/门槛/完成准则 |
| 后续要做 | 缺陷台账（人工镜像+机读 bugQueue）+ 评审侧 issues | 缺陷流转/跟龄/复验 |
| 历史 | 文末 Changelog（唯一合法位置） | 各版本变更 |

## 三件套拆分清单（29119-3）

从常驻契约中识别并下沉执行层的内容：
- 启动自检脚本（probe）→ `<项目>/tests/scripts/probe-*.sh`（Linux/mac）/ `probe-*.ps1|*.mjs`（Windows）或 playbooks
- 命令手册/命令索引/探测脚本 → `<项目>/tests/playbooks/<name>-procedure.md`
- 端点基线表 → `<项目>/tests/fixtures/<name>-endpoint-baseline.md`
- 测试账号表 → `<项目>/tests/fixtures/<name>-accounts.md`（真值引用密钥源）
- AI 判据 golden set → `<项目>/tests/fixtures/ai-golden-set.json`

契约原位留指针块（一句话路径+「本契约只保留判据与门槛」），保持契约可读性。

## 治理工作守则

1. 产出=草案/递单，不改项目规范正典（`<项目>/docs/`），转正走维护人；任务内明确授权除外（报告注明出处）
2. 治理前后做完整性核验：⛔/⏭️/⏸️ 门槛零丢失、表格行数对账、AC-ID 无重号
3. 一切清理可回放：变更清单写入 Changelog 新条目，不静默改
