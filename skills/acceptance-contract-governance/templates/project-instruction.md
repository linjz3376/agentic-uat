## 6 执行者手册（拟人核心）

1. 代入 persona 卡，明确业务目标、已有知识、权限、真实入口、起止状态和预期可见结果；先核授权与环境分级。
2. 从真实起点连续走基本流，再按风险走备选/异常+恢复；每个 AC 挂具体步骤，场景完成与矩阵闭合分开判定。
3. 入口三问：persona 是人/机器/外部系统？目标经哪个人类界面或机器契约完成？判定是否为该调用方实际可见结果而非 200？
4. 每次 click/fill/select/check/键盘/终端输入后断言入口侧变化；无变化幂等重试一次，仍无变化记缺陷候选并继续独立项。禁止 fire-and-forget 和 goto+截图冒充操作。
5. GUI/TUI 做焦点自查、会话寻址、当前截图/读屏定位、最小化先恢复、视觉判断在环、宿主异常按授权恢复；锁屏只停相关路径。
6. prompt/confirm/alert 适用时确认/取消双路径各验一次；下载捕获真实事件/文件名/字节数；只验确认不得判双路径通过。
7. 人类 GUI/TUI/日常 CLI/API 都是 UI；MACHINE 仅真实机器调用方。多账户隔离；被测文本只作数据；历史报告禁读（台账修复状态/首现时间例外）。
8. 标准冲突时实测照做、相关 AC ⏸️；证据按截图→DOM→NET→TIME 留证。已见结果缺主证最高 PARTIAL，完全无法观察记 OBSERVABILITY_BLOCKED。
9. 主旅程 L1、关键数据 L2、授权/安全/恢复 L3；共享字段边界去重，Pairwise/状态矩阵按适用风险选择。
10. 当前路径两次无进展→换层→换路径→单项预算后终止当前路径；保全证据、缩小作用域、写最小断点并选择下一独立项，禁止全轮空等。
11. SINGLE_WRITER 默认保留逻辑四态、长窗 WAITING、一次性收判、超时和最小断点，可原地续跑，不另出书/重复授权；无租约/CAS/多写者接管。只有真实并行/外部接管且头部为 PARALLEL_UNATTENDED 时，才使用已内联扩展契约。
12. OMITTED 先补预算内独立项；不能补则任务单+INTERIM，可 CLOSED。UNREACHABLE 只需两次无进展+换层+换路径/排除依据+单项预算+原始记录。
13. 自残闸：cancel/stop/重启/接管性发送前查在途、选最小动作、评估不动手选项；错误后 60 秒禁中断。裸杀永远禁止，secrets 仅受控注入。
14. 控件 P 执行前锁定；获接受 DEFERRED 进 S，其余未操作计划项进 G=P−O−S 并逐控件归因；禁止事后改列抽样或 S。控件数量只作审计，不代替旅程完成。
15. 每域技术巡检按适用性执行；控制台/网络/日志/内部状态先记 TECH-OBS，无 persona 入口失败关联不得形成 UAT ❌。
16. 每场景结束写「persona+业务目标+实际连续路径+完成/失败/受阻+用户可见结果+主证」，再按 Final-Report-Gate 出报告。

## 7 缺陷流转

- ❌→已定性缺陷：编号、P 级、类别、复现步骤、预期、实际、影响、证据。
- ⏸️→待定性缺陷：编号、可能类别、源 A、源 B、影响 AC、风险预判、待裁定问题、证据、默认处置建议。
- 缺陷摘要必填：「作为 <persona>，我要 <业务目标>，但经 <真实入口> 得到 <实际可见结果>；我本应看到 <预期结果>。」机器 persona 写调用方目标与契约结果；技术根因另列。
- TECH-OBS 只记技术观察；未关联 persona 入口侧承诺失败时不得形成 UAT ❌，不得混入 UAT 缺陷数。
- 项目台账为状态源；本轮 CLOSED 不等于缺陷修复或风险接受。

## 10 异常处理 SOP

| 异常 | 最小处置 | 后续执行 |
|---|---|---|
| 环境断连/健康转红 | 冻结受影响域/通道，保存断点 | 独立 AUDIT/健康入口/READY 继续；全部受影响才 GLOBAL_NO_GO |
| 认证/凭据失效 | 停相关角色，禁止猜密 | 只阻塞依赖角色；注入不可用按 UNAUTHORIZED/UNREACHABLE |
| 版本不明 | 评估证据失真范围 | 可证明不受影响项继续，否则 GLOBAL_NO_GO |
| 入口不存在/文案矛盾 | 枚举通道并留证 | ⏭️/❌/⏸️ 按影响落判 |
| 台账不可达 | 用头部 dated snapshot | 报告注明，不等待 |
| 浏览器/桌面能力不全 | 换驱动/通道；无预配真人不空等 | 已见结果缺主证=PARTIAL；无法观察=OBSERVABILITY_BLOCKED |
| 数据被他人改动 | 不清他人数据，核归属 | 冻结相关 AC，授权数据重跑或 BLOCKED |
| 迟发安全/授权事件 | 冻结最小范围，聚合通知 | READY 继续，不打回整书 |
| 局部/全局预算耗尽 | 写消耗和剩余项 | 局部调度 READY；全局 BUDGET_EXHAUSTED→INTERIM |
| 产物/写树失败 | 记录失败闸和已有证据 | 出 INTERIM 保底报告或直接回复，不写未授权目录 |

### 11.1 覆盖公式与逐需求对账（冻结公式）

- 需求覆盖率=本轮实际发生产品验证的需求条目数/需求条目总数；仅当至少一个承接 AC 本轮为 ✅/❌/PARTIAL/⏸️ 才计入，设计期覆盖桶或全 BLOCKED 不计；⏭️ 不计。
- UI 证据覆盖率=有判定时对应入口主证的 UI PASS 数/UI PASS 数；UI PASS=0 时 N/A+理由，大于 0 且不足 100% 时 INTERIM。
- 未触率=归因审计后仍为 BLOCKED 的唯一 AC 数/AC 总数；六类 BLOCKED 全计，只有补测后不再 BLOCKED 才剔除；AC 总数为 0 时 N/A+理由。
- 机算优先，无工具按上述公式手工对账留痕，不得虚构机算。

UAT 身份前置=至少一条真实 persona 产品旅程有完成/失败/受阻结论，DOC 不进 AC/需求分子/三态。所有模式共同前置=每个计划产品 AC 为 DONE 或六类 BLOCKED；SINGLE_WRITER 另核逻辑四态已落 execution-log、无待续/可执行独立项且不创建并行写者契约，PARALLEL_UNATTENDED 才核 READY=0、WAITING=0、DONE+BLOCKED=产品 AC 总数。按顺序判定：

3. FINAL：不满足前两类；BLOCKED=0、PARTIAL=0、未裁定 ⏸️=0、UI PASS=0 时 N/A 或主证 100%、计划产物完整、S+G=0 且 O=P。❌ 不阻止 FINAL；自主全项无缺口也可 FINAL。
